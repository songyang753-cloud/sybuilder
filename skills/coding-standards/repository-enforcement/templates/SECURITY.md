# 安全策略（Security Policy）— 模板

## 报告漏洞
请**私下**报告（勿在公开 Issue 披露）：
- 邮件：<security@example.com>（替换为实际安全联系）
- 包含：影响范围、复现步骤、PoC（如有）、建议修复
- 我们将在 <N> 个工作日内确认，修复后致谢（除非要求匿名）

## 支持范围
当前维护分支：<main>。仅对受支持分支提供安全修复。

## 安全基线（详见 docs/ENGINEERING_STANDARDS.md §4）
- <认证机制> / <授权模型>
- 服务端为权威输入校验
- 密钥仅经环境/密钥管理注入，永不入库；CI 跑密钥扫描
- 管理操作落审计日志

## 密钥泄漏处置
一旦发现疑似密钥进入仓库（含历史）：
1. **立即轮换**（视作已泄漏，不论是否被利用）
2. 从代码移除，改为环境/密钥管理注入
3. 评估影响面与访问日志
4. 已进入历史则按需清理（git filter-repo）并强制轮换
