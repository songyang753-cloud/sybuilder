## P0 · 先交给工具，别写进规范

写进规范靠人记的每一条，都会有人忘。以下一律配置化，**规范里只留一句「按仓库配置执行」**：

| 类别 | 交给 |
|---|---|
| 缩进 / 换行 / 引号 / 分号 / import 顺序 | formatter（prettier / gofmt / black / rustfmt / ktfmt） |
| 命名大小写风格、未使用变量、可疑相等 | linter（eslint / clippy / ruff / rubocop / checkstyle） |
| 类型错误、空值穿透 | 类型检查器（tsc / mypy / 编译器） |
| 已知漏洞依赖 | 依赖扫描（走**官方源**，见 A2 的反例）。⚠️ **扫漏洞只是供应链的一小半**——锁文件与 frozen 安装、来源与校验和、provenance/SBOM、install script 审查在 **M6**（交付层） |
| 提交信息格式 | commitlint / 约定式提交校验 |

**同理，能交给「栈专属 skill」的，也别写进这份跨栈规范。** 本机已装的 89 个相关 skill 呈现出一个稳定形状：
**每个栈一套「安全 / 测试 / 验证闭环」三件套**（`django-security` + `django-tdd` + `django-verification`；
`laravel-*`、`quarkus-*`、`springboot-security`、`golang-testing`、`react-performance`、`cpp-coding-standards` …）。
⇒ 本文只写**跨栈都成立**的判断；「这门语言里这类问题长什么样」交给对应的栈专属 skill 或语言官方规范。

> **50 份文档里有 20 份以上把这些写成人肉条款**——那是它们成文早于工具成熟。今天再写进规范，只会稀释真正需要人判断的条款。
> ⚠️ 但要按 A1 检查这些工具**真的在跑**：配置文件存在 ≠ CI 在执行 ≠ 执行结果被采信。

## P1 · 真共识条款（50 份里高频出现且无实质分歧）

**命名**（依据：kettanaito/naming-cheatsheet 的 A/HC/LC 模式、ktaranov/naming-convention、各语言 style guide）

- 名字要 **S-I-D**：Short（短）/ Intuitive（直觉）/ Descriptive（描述性）——三者冲突时保 Descriptive。
- 布尔用 `is` / `has` / `should` / `can` 前缀；集合用复数；`min`/`max`、`prev`/`next` 成对。
- 动作动词要有**项目内固定**的含义，别混用：`get`（取）/ `set`（设）/ `reset`（复位）/ `compose`（由已有造新）/ `handle`（响应）。**「可逆的移出」与「不可逆的抹除」混用是高频真缺陷**。⚠️ 2026-09-10 外部评审纠正：**别把 `remove`=移出、`delete`=抹除当成跨语言通则** ——`Map.delete()` 只是移出集合、DOM 的 `remove()` 是脱离树、HTTP `DELETE` 也未必物理抹除。⇒ 先服从语言/框架/领域惯例；项目内部则明确区分 **detach / archive / disable（可逆）** 与 **erase / purge（不可逆）**，并把生命周期写进 API 契约——**不许只凭名字推断它删没删干净**。
- 避免缩写；避免上下文重复（`User.getUserName()` → `User.getName()`）。
- 名字要**反映期望的返回**（返回布尔的别叫 `checkPermission`，叫 `hasPermission`）。

**函数与控制流**

- 早返回 / 卫语句代替深嵌套；嵌套过深就重构（**常见启发阈值 ~4 层,按语言/项目调,不是硬线**）。
- 一个函数一个抽象层次；参数偏多考虑传对象（**~3 个是经验参考,不是红线**）。
- 命令与查询分离（CQS）：改状态的别返回值，返回值的别改状态。
- 副作用要显式——纯函数优先，不可变优先（用户全局规范同款）。

**错误**

- 不吞错误；不写空 `catch`（⚠️ 有例外且例外承重：fire-and-forget 与插件宿主的 catch-and-log **是对的**，
  别为迎合本条改成 throw / 脆弱匹配——正本见 K9 镜像面；此处按绝对句执行会改坏正确代码）；
  错误要保留原因链（Go 的 `%w`、异常的 `cause`）。
- 错误信息给出**可操作的下一步**，不只是「失败了」。
- 面向用户的文案与面向日志的上下文分开：前者可读，后者可查。

**依赖与结构**

- 高内聚低耦合；依赖倒置（依赖接口不依赖实现）；组合优于继承。
- 迪米特法则：只和直接朋友说话。
- 文件按特性/领域组织，不按类型组织（依据：kriasoft/Folder-Structure-Conventions、Sairyss/domain-driven-hexagon）。
- **为删除而优化**（Optimize for Deletion，webpro/programming-principles）——能被整块删掉的模块，边界大概率是对的。

**变更与提交**（依据：google/eng-practices、conventional-commits、agis/git-style-guide）

> 小变更与可评审性指导选译自 Google Engineering Practices（Google 及贡献者，CC BY 3.0），
> 已做精简并加入本地说明，不是官方译本；[许可](../../../licenses/google--eng-practices.txt)
> 与 [来源版本](../../../licenses/sources.json) 须随改编内容保留。

- **一个 CL 只做一件事**，且小到能被一次看完。Google 的判据：*reviewer 能不能在合理时间内完整理解它*。
- 提交信息第一行说**做了什么**，正文说**为什么**——「为什么」在 diff 里读不出来，「做了什么」能。
- 重构与功能变更**分开提交**（混在一起时 review 只能看懂其中一半）。

**API**（依据：microsoft/api-guidelines、zalando/restful-api-guidelines、rust-lang/api-guidelines）

- 向后兼容是默认承诺；破坏性变更走版本，不走「顺手改了」。
- 错误响应结构统一、可机读；分页/排序/过滤参数命名全局一致。
- 接口对**非法状态不可表示**优于运行期校验（依据：rust-lang/api-guidelines 的类型设计条款）。

**安全**（依据：OWASP/CheatSheetSeries、OWASP/Go-SCP、transmissions11/solcurity）

- 参数化查询，不拼 SQL；输出按上下文转义（HTML/属性/JS/URL 各不同）。
- 不信任何客户端来的东西，包括文件名与 Content-Type。
- 密钥不进源码、不进日志；⚠️**按长度决定打不打印是错的判据——短值恰恰是人设密码**。需要关联日志时**不输出任何原文片段**（连前 4 字符也会缩小攻击空间）：优先只记**凭据 ID / 版本 / secret manager 路径**。⚠️ **别用 `sha256(secret)[:8]`**（2026-09-10 外部评审纠正，此前本文推荐过它）：8 个十六进制字符只有 **32 位**，约 7.7 万个值就到 50% 碰撞；更要命的是**无密钥**哈希对低熵口令/短 token 可以**离线字典比对**，且同一密钥在不同服务里算出同一个值 ⇒ 可跨系统关联。确有关联需求时用**专用日志密钥**做 `HMAC-SHA-256(logKey, secret)` 并保留 ≥128 位，同时定义该 logKey 的轮换与访问控制。

## P2 · 真有分歧的条款（别当定论，按项目选边并写下理由）

这几条在 50 份文档里**互相矛盾**，且矛盾是实质性的。规范该做的是点名分歧、给决策依据，而不是假装有标准答案。

> ✅ **2026-09-05 已回原文核对**：「函数该多小 / 注释该多少 / 要不要 TDD」三条分歧
> 均出自 `johnousterhout/aposd-vs-clean-code`（Ousterhout 与 Martin 的公开对谈全文）。
> 上面引的两个数字在原文可查：`5-10x more lines of comments`、
> `the cost of missing comments is easily 10-100x the cost of incorrect [comments]`。
> 核法：`gh api "repos/johnousterhout/aposd-vs-clean-code/contents/README.md" --jq .content | base64 -d | grep -n "5-10x"`

| 争议点 | 一方 | 另一方 | 怎么定 |
|---|---|---|---|
| **函数该多小** | Clean Code：小到不能再小，一个函数只做一件事 | APOSD（Ousterhout）：过度分解会**增加**理解成本，被拆开又互相纠缠的方法比不拆更难读 | 判据换成 **「读懂这个函数，脑子里要同时装多少信息」**——装不下就拆，拆完还要回头看兄弟函数才懂，就是拆过了 |
| **注释该多少** | Clean Code：注释多为失败的表现，能用代码表达就别写注释 | APOSD：注释承担代码表达不了的信息，**缺注释造成的损失远大于坏注释**（原话：缺注释的代价「轻易是错注释的 10–100 倍」；他自称对同一段代码会写 **5–10 倍**的注释行数） | 本文取**中间且更严的立场**：注释可多可少，但**写下的每一句都是承诺，必须能对账**（见 E1/E2）。不对账的注释，多写就是多欠债 |
| **要不要 TDD** | Clean Code：短周期先写测试 | APOSD：TDD 会**鼓励坏设计**，「打包式」后写测试可得同样效果 | 本文只要求 **缺陷类改动必须先红后绿**（C5）——那不是 TDD，是可复现锚点。新功能用哪种节奏，项目自定 |
| **DRY 抽多早** | 多数指南：见到重复就抽 | 用户全局规范 / YAGNI 派：重复是真的才抽，不为投机性复用抽 | **三次法则** + C2 三查：抽之前先确认它们是**同一个理由**在变，不只是长得像 |
| **防御性编程的度** | 防御派：处处校验 | 简单优先派：不写不可能场景的错误处理 | 按**信任边界**分：跨边界（用户/网络/文件/IPC）必校验，边界内信任类型系统 |

## P3 · 经典条款被承重层修正的地方 ⭐

**这一节是本文相对于那 50 份文档的主要增量。** 左列是它们的原话，右列是承重层实证要求补上的东西——不是推翻，是**它们停在了半路**。

| 经典条款 | 停在哪 | 承重层补上 |
|---|---|---|
| 「处理错误，不要吞」 | 只讲了**会抛**的错误 | **A2**：错误有三态，第三态（能解析但缺预期字段）**不抛**，于是走进成功分支。`\|\| {}` `?? 0` 出现在解析外部响应处默认是缺陷 |
| 「校验输入」 | 只讲了「在边界校验」 | **B1**：校验写在**发起方**等于没写——执行点必须在特权方，且特权方自己从权威来源推导规则 |
| 「校验输入」 | 只讲了单条路径 | **I1**：per-item 收口 ≠ 列表/队列/聚合/导出收口，要按全部触达面穷举 |
| 「用命名常量代替魔法数」 | 常量有了就完了 | **A4**：截断类常量（前 N 条）要把**标志跟着数据传到消费方**——限制是有意的，缺的是标志 |
| 「DRY，重复就抽取」 | 只讲收益 | **C2**：抽取必然伴随三种静默损坏（判据留在原地 / 语义收窄 / 上报了没收下），每次逐条核 |
| 「写注释解释 why」 | 把注释当**说明** | **E1/E2**：注释是**承诺**，而且会**诱导读者**不去数边界。写下即欠账，必须能指到实现路径 |
| 「提高测试覆盖率」 | 只问「这行跑到了吗」 | **D1**：不问「跑它的那个输入像不像真的」。夹具必须来自生产路径 |
| 「写测试」 | 假设测试可信 | **D2/D3**：断言要能红；判据式要有两个方向的反例 |
| 「fail fast」 | 快速失败 | **A1**：前提是能分辨 **FAIL 与 UNABLE**——「没能测」被当成「测过了不合格」就是假红 |
| 「重试 + 退避」 | 讲了退避 | **G2/F1**：无上限重试即缺陷；每个阻塞点要有**墙钟**超时；**E4** 内外层超时不得相等 |
| 「小 CL / 小 PR」 | 讲了大小 | **C1**：判据不是行数，是 **diff 里每一行都能追溯到那条需求** |
| 「面向接口编程」 | 讲了解耦 | **B3**：注册器与执法器是两个面，**执法器不得比注册器松**，否则是不需要写代码的后门 |
| 「常量与配置外置」 | 外置就完了 | **B8**：交出去的配置要 `Object.freeze`——否则调用方投毒是静默生效（⚠️ 它是**浅冻结**，嵌套字段照样可改——要递归 freeze 或交深拷贝，适用条件见 B8 正本）。<br>⭐ 另一个角度（2026-09-05 实测）：外置不只是「别写死值」，是**能不能起第二个实例**。一个常驻中转服务把端口写成 `PORT = 8787`，而它是全机所有会话的上游 ⇒ **「验证改动」和「打断所有人」是同一个动作**。可测试性是**设计属性**，不是测试的责任 |
| 「监控与可观测性」 | 加指标 | **A5**：新增诊断字段必须有人**读并断言**，否则它只会让判据更容易过 |
| 「数据驱动 / 配置驱动」 | 把事实挪进数据文件 | **J1/J2**：数据里的事实要和**外部权威源**比对；代码常量与数据文件要做集合差集 |
