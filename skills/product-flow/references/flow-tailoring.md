# 运行方式与流程裁剪：完整运行 · 独立模块 · 声明阶梯

## 一、两种运行方式，完成的含义不同（2026-09-07 按 Codex 外审立）

| 方式 | 保证什么 | 最高声明 |
|---|---|---|
| **完整运行**（S1→S10） | 端到端价值 + 跨产物一致性 | `integrated-frozen`（G7.5 后）；S8 方案批准后可进入交付；上线观察后 `production-validated` |
| **独立模块**（`--only`） | 模块内部完整、可交接、可被完整流程导入 | `module-approved` —— **不是缩水版全流程，也拿不到三方冻结** |

### 完成声明阶梯（低一级不许用高一级措辞）

| 级别 | 含义 |
|---|---|
| `exploration` | 探索方向，关键输入仍是假设 |
| `draft` | 产物结构完整，关键决定或验证未完成 |
| `review-ready` | 模块内容完整、内部门禁过，可交人评审 |
| `module-approved` | 模块在自身权威域内已批准，handoff/delta 完整 |
| `integrated-frozen` | PRD/Figma/HTML 完成 G7.5 三方冻结 |
| `production-validated` | 最终应用四方对账 + 真实上线观察（⛔ 模板测试拿不到这一级） |

⛔ 「PRD 完成」必须说清是 **v0.9 基线 / 独立模块批准 / 回灌后的 v1.0**。
依赖飞书/Figma/HTML 的模块，`module-approved` 还要求原生产物已生成并回读；
只有本地 MD/导出/截图/链接时，最高只能是与证据相符的 `draft`/`review-ready`。

`references/workflow-registry.json`。每次都先用 `scripts/product-flow-run.py plan`
生成运行合同，禁止手填 manifest。文案与注册表冲突时先停并修复冲突。

### 独立模块的七步小闭环（`--only <模块>` 一律走这套，不是直接套模板）

1. **Route** 确认用户要的模块与交付级别 → 2. **Intake** 读最小输入，记录访问等级
（原生/镜像/截图/链接）与版本 → 3. **Gap** 缺口分三类：可假设（ASM-xxx）/必须停止（SL-xxx）/
N/A —— ⛔ **不许伪造空上游文件让路径检查通过** → 4. **Work** 模块内部循环 →
5. **Validate** 只跑本模块适用门禁 → 6. **Backfill/Handoff** 对上游出 delta
（`templates/prd-backfill.md`）、对下游出交接物与未关闭依赖 → 7. **Claim** 用
`product-flow-run.py result` 把 `templates/module-result.json` 签发到
`.product-flow/runs/<runId>/modules/<moduleId>/<resultId>.json`——声明结果、证据与级别上限
（⛔「本模块验不了什么」必填；禁止复用根目录固定文件名）。需要人读摘要时，可用
`templates/module-result.md` 生成同目录 `<resultId>.md`，但机器导入只认已签发 JSON。

独立产物进完整流程要 **import 校验**（版本/权威/未关闭依赖），不能因为路径相同就默认可信。
组合模块按**依赖拓扑**跑（如 `design,prd` 先 PRD 基线再设计再回灌），不按用户书写顺序盲跑。

# 流程裁剪：这个项目到底该跑多重

> 2026-08-31 第十一轮补入。起因：Codex 外部评审指出——
> SOP **知道**「过度形式化是缺陷」（铁律 39），但**没有任何可执行的裁剪机制**，
> 结果内部工具、消费级 App、新业务探索被同一套重量级流程约束。
>
> ⚠️ **本篇给的是「怎么裁」的机制，不是「裁多少」的定值。**
> 各档具体裁哪些环节**尚未经过真实项目校准**——见文末「诚实边界」。

## ⭐⭐ 〇之前：三个词不是一回事（2026-08-31 补，外部评审揪出）

本 SOP 此前把三件事都叫「跳过/裁剪」，于是执行者可以自行解释。现在分开：

| 词 | 含义 | 允许吗 |
|---|---|---|
| **乱序** | 跳过先决条件向前推进 | ⛔ **永远不许**（铁律 1）——ID 链会断，后面所有对账失效。⚠️ **不包括**：登记过的合法回路（回退重做，留痕）、已上线产品的 baseline 反推、`--only` 具名模块单跑——这些是有合同的路径，不是乱序 |
| **裁剪** | 某个阶段**整段不跑** | ✅ 允许，但**必须在 `scope.md` 里开工前声明** |
| **降级** | 阶段跑，但只跑其中一部分 | ✅ 允许，同样要声明降到什么程度 |
| **裁掉但要补证据** | 阶段不跑，**但它守的那件事必须换个方式被守住** | ⚠️ 这是最容易被含糊过去的一类，见下 |

⭐ **第四行是关键**：有些阶段可以不跑，**但它守的东西不能没人守**。
例：裁掉 S6 demo（已上线产品）→ **必须锁 `baseline.md`**，否则 G2/G3 进 UNABLE。
⛔ **「裁掉了所以不用管」是错的**——那叫漏，不叫裁。

⛔ **完整运行里不许裁的决策职责**（档位只能调深度/候选数/覆盖批次/验证规模）：
S2 研究、S3A 业务梳理、S3B Go/No-build、S4A 产品结构、核心三件套（PRD/Figma/HTML）、
S8 技术/算法/测试联合方案、S9.3 产品验收。裁其中任何一个＝把缺口挪到下游且不留痕。

## 〇、⭐⭐ 最重要的一条：裁剪必须留痕，不许临场跳过

**这套 SOP 最可能的失败不是漏步骤，是执行者中途疲劳后形式化打勾。**

⛔ **被裁掉的环节和「跑了但没发现问题」的环节，在产物上长得一模一样。**
所以裁剪必须在**开工前一次性声明**，写进 `.product-flow/scope.md`，
并且每条都带**理由**与**如果这个判断错了会怎样**。

⛔ 中途想跳过某一步 → 回到 `scope.md` 改声明并写明为什么改，
**不许在执行时静默跳过**。静默跳过的那一步，事后无人能分辨它是被裁了还是被忘了。

## 一、先答五个问题（`scope.md` 第一节）

| # | 问题 | 取值 |
|---|---|---|
| 1 | **可逆性** | 大部分是双向门 / 含关键单向门（数据格式、对外协议、定价、品牌） |
| 2 | **量级** | 影响几个人 / 一个团队 / 全部用户 / 涉及钱或合规 |
| 3 | **谁来接** | 就我自己 / 一个熟悉背景的人 / **一个没参与过讨论的团队** |
| 4 | **产品形态** | 内部工具（单一操作角色）· 消费级 · B2B 多干系人 · 合规更新 · 存量改造 |
| 5 | **不确定性在哪** | 不知道该做什么（WHAT 未知）/ 知道做什么不知道怎么做（HOW 未知）/ 都清楚只是要做 |

⭐ **第 3 问是权重最大的一问**：
**这套 SOP 一大半的机制（ID 链、双向对账、格式边界、元素身份）
存在的唯一理由是「有人要接手，而他不在你脑子里」。**
如果答案是「就我自己，两小时能重写」——**大部分机制对你是纯损耗**（铁律 1 的前提）。

## 二、三档（默认建议，待真跑校准）

⚠️ **适用范围**：三档是**独立/组合运行**选深度用的；**完整运行**（声称走完整流程）不适用「可裁」列——
完整运行只许降深度/减候选/缩批次，⛔ 不许删决策职责（见上「完整运行里不许裁的决策职责」）。
**轻档实质是「不走完整流程」的替代基线**：产出按 `templates/module-result.json` 的声明上限封顶，不得声称走完了 SOP。

| 档 | 什么时候 | 必跑 | 可裁 |
|---|---|---|---|
| **轻** | 自己接 · 双向门 · 两小时能重写 | S1 定义 · S3 一句话产品定义 · 直接做 | S2 全部 · S4 完整 PRD · S5–S7 全套 · 多轮评审 |
| **中** | 有人接但熟悉背景 · 双向门为主 | S1 · S2（**只做需求侧竞品 + 差异化那一段**）· S3 · S4 正文 + 附件 A/B/G.1 · S5 · S6 · S8 · **S9** · **S10** | S2 五条线跑满 · S7 Figma 可降级 · 11 视角终审（改 5 视角）· S10 可降级为**目标账 + 假设账**两本 |
| **重** | 团队接 · 含单向门 · 涉及钱/合规/对外协议 | **全部阶段都要跑到** | ⛔ **不许整段裁掉**；可以**降级**（如 S7 用已有设计系统而非新建基座），但降级要声明 + 写明谁承担后果 |

⚠️ **档位不是按项目大小定的，是按上面五问定的。**
一个两周的小功能如果改了对外数据格式，它是**重**档。

## 三、⛔ 任何档都不许裁的四样

无论多轻，这四样是这套 SOP 的地基，裁掉它就不是这套 SOP 了：

1. **人拍板点不许代劳**（铁律 9）——轻档也一样，只是拍板的形式可以是一句话
2. **不确定的事实必须标来源**（M2 三来源）——`[ASM]` 一个字都不能省
3. **没真跑的记 SKIPPED / UNABLE，不许折叠成 PASS**
4. **裁剪本身要留痕**（本篇〇节）

⭐ 前三条的共同点：**它们防的是「我不知道自己不知道」**，
而这件事和项目大小无关。
