# 就绪度判定

**这一步的产出可能就是全部产出。** 如果 PRD 撑不起用例，缺口报告就是本次交付，不要为了"有东西交"而生成猜出来的用例。

## 判定表（逐功能核，不是整份文档核一次）

对每个功能 `F-xx` 逐项打勾：

| # | 检查项 | 判据（能回答就算有） | 缺了的后果 |
|---|---|---|---|
| R1 | 验收标准 | 有 `FR/AC` 或等价的可判定条件 | 用例没有预期结果 |
| R2 | 字段级规格 | 每个输入字段的类型/必填/长度/取值范围/校验规则/错误文案 | 输入类用例全靠猜 |
| R3 | 异常场景 | 网络失败、无权限、空数据、超时各自的表现与用户下一步 | 只剩 happy path |
| R4 | 状态清单 | 空态/加载/成功/失败/无权限/极值 | 状态类用例缺失 |
| R5 | 权限与角色 | 谁能做、谁不能做 | 越权用例无从设计 |
| R6 | 数据边界 | 最大条数、并发、超时阈值 | 边界/性能用例无依据 |
| R7 | 前后置依赖 | 依赖哪些前置数据/状态 | 用例前置条件写不出 |
| R8 | 可测性 | 有无「美观」「友好」「流畅」这类无判据表述 | 这些条目不可测，是 PRD 缺陷 |
| R9 | **安全与合规依据** | 有无 PRD 附件 C：数据清单、**角色权限矩阵（含每个"不允许"）**、产品级安全规则、合规约束 | 产品级安全用例（越权、脱敏、审批、留存）**全部无从设计** |

⚠️ **R9 缺失不等于不做安全测试**：工程基线类安全用例（注入 / XSS / 限流 / 信息泄露）属于工程标准，**PRD 没写也照测**（见 `s9-quality-gates.md` §一“双轨制”）。R9 卡住的只是**产品级**规则——谁能看谁的数据、导出要不要审批。这两类不要混为一谈：前者漏了是失职，后者猜了是越权替产品做决定。

## 结论只有三种

| 结论 | 条件 | 该做什么 |
|---|---|---|
| **可生成** | R1-R4 齐备，R5-R7 齐备或明确不适用 | 进入抽取与设计 |
| **部分可生成** | 部分功能齐备、部分缺 | 对齐备的生成；缺的列缺口，用例集中标 `[待补规格·不生成]` |
| **不可生成** | R1 或 R2 大面积缺失 | **只出缺口报告**，停在这里 |

⚠️ 不存在第四种结论。**尤其不存在「基本可以，我按常规补一下」**——那是把编造包装成效率。

## 缺口报告格式

```markdown
# 就绪度判定　日期：2026-08-16　文档：<PRD 名称 v1.2>

## 结论：部分可生成（8 个功能中 5 个可生成，3 个缺规格）

| 功能 | R1 验收 | R2 字段 | R3 异常 | R4 状态 | 结论 |
|---|---|---|---|---|---|
| F-01 登录 | ✅ | ❌ 无任何字段规格 | ✅ | ⚠️ 缺无权限态 | 不可生成 |
| F-02 列表 | ✅ | ✅ | ✅ | ✅ | 可生成 |

## 缺口清单（要补什么，谁来补）

| ID | 功能 | 缺什么 | 具体到什么程度才够 | owner |
|---|---|---|---|---|
| GAP-01 | F-01 | 手机号/密码的字段规格 | 类型、必填、长度、格式、校验失败文案 | <产品> |
| GAP-02 | F-01 | 无权限态表现 | 页面显示什么、用户下一步能做什么 | <产品> |
| GAP-03 | F-05 | 「响应流畅」无判据 | 改成具体阈值，如「≤300ms」 | <产品> |

## 本次不生成的部分
F-01、F-03、F-05 共 3 个功能，等 GAP-01~03 补齐后再生成。
**已生成部分的覆盖率不包含这 3 个功能**（分母只算真核过且可生成的需求项）。
```

## 硬约束

- ⚠️ **逐功能判，不许整份文档一句话结论**。「这份 PRD 写得挺全的」不是判定。
- ⚠️ **缺口要具体到"补到什么程度才够"**。只写「缺字段规格」，产品补回来的多半还是不够用，来回两轮。
- ⚠️ **每个 GAP 要有 owner**，无 owner 的缺口等于永远不会被补。
- ⚠️ **空缺口清单是可疑信号**。真实 PRD 极少八项全备——判定结果全绿时，回头确认是不是自己放宽了判据。
- ⚠️ **不可测表述必须点名**（R8）。它们通常写在最显眼的地方，且最容易被当成"已经有要求了"。
- ⚠️ **缺口登记只有一个入口：`readiness.md` 的缺口清单表**。写用例过程中新发现的缺口（很常见——真到动笔才发现某个预期结果 PRD 没写），必须**回填到这张表并顺延编号**，不许只在用例备注里写一句「见 GAP-09」就完事。
  📌 2026-08-16 演练实录：我在一条用例备注里引用了 `GAP-09`，而缺口表只登记到 `GAP-08`——**这个编号指向一个不存在的东西**。缺口从两个地方产生，就一定对不上；对不上的缺口没人会去补。
  ⚠️ 自检：报告里出现过的最大 GAP 编号，必须能在缺口表里找到。找不到＝有缺口没回填＝**本次交付未完成**。
