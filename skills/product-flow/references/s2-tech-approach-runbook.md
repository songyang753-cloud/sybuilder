# S2 · tech-approach 模式 runbook(技术方案调研)

> **何时用本模式**:调研对象是**代码实现 / 技术机制 / 行业技术方案**,目的是**为设计自家方案提供可抄的判据**。
> 反例:「调研相册竞品」≠本模式(走 teardown/competitive);「调研开源相册的索引实现」「调研手机助手的意图分发方案」=本模式。混合任务两模式并行、各出各的产物。
> 本模式**不做 UI 遍历**:证据来自源码实读与案头调研，S2 的 GUI 遍历与竞品正文门不适用；技术结构门、通用受众/质量评审和所选平台全文/图片交付门仍必跑，不能以模式切换免除真实图与原生页面审核。
> 判据来源:2026-09 「A2A 意图分发调研」实跑复盘——19 次用户提醒逐条沉淀,每条判据可回溯一次真实返工,零投机项。

---

## 一、开工对齐:五项假设表(第一动作,治最贵的三类返工)

**形态是「亮出推断好的默认答案」,不是问五个空白问题**——契合「显式假设+自主推进,只在真岔路停」。

| 项 | 内容 | 默认推断规则 | 阻塞? |
|---|---|---|---|
| **A1 下游用途** | 调研完拿来做什么方案/决策 → 直接决定聚焦维度与摘要成节 | 任务描述里找项目线索(如「我们在做 A2A 项目」⇒ 用途=为其设计分发方案) | 否 |
| **A2 受众** | 只技术 / 产品+技术(决定是否要产品共读层图文) | 下游含产品决策 ⇒ 双层 | 否 |
| **A3 载体+账号** | `documentPlatform`(feishu/dingtalk)+ **`deliveryAccount`**(具体账号/租户名) | 从用户记忆取默认值 | **是** |
| **A4 深度档位** | 摘要级 / 机制级 / **方案级(默认)**——方案级=每个策略决策点可照抄(定义见三) | 下游用途=做方案 ⇒ 方案级 | 否 |
| **A5 对象清单+排序** | 逐个列名(双轨选样,见二)+ 排序原则 | 见二 | **是**(=校准门) |

- 五项一次性亮出(每项:假设值 + 推断依据),写入 `scope.md` 并发给用户;仅 A3/A5 阻塞,其余按假设推进。
- **单跑自足**:用户直接说「帮我调研 X」(=`--only research`)时,假设表**不依赖 S1 产物**,在 S2 开工自足完成;走全流程时,A1/A2/A4/A5 从 S1 `intent.md` 五要素特化映射(成功长什么样→A1、谁用→A2、约束→A4、范围→A5)。
- ⛔ 五项都必须出现;「用户没说」= 必须推断并亮出,不是省略的理由。
- `scope.md` 同时声明机检口径:`object_count`(对象数)及其显式豁免清单(如「首批 20 家」这类历史性表述)。

## 二、对象选择与校准门

- **双轨选样**:①热度轨(star/采用度)②**相关性轨**(与 A1 下游用途最相关的**产品级实现**;同类最强产品默认入围——实跑教训:只按 star 选样漏掉了用户眼中最重要的 OpenClaw/Codex/Cline)。
- **排序默认按相关性/能力完整度分梯队**,⛔ 不按纯热度;总览表(`2.0` 节)带梯队呈现。
- **校准门 = A5 确认**(不可跳过):对象清单+排序+深挖档位,深挖开始前用户确认;确认前只做不受影响的案头部分。「选错对象再分析得再好也是最贵的失败」。

## 三、逐对象产出判据(方案级深度)

统一编号 `2.N 对象名`,每对象四节:

| 节 | 内容 | 配图 |
|---|---|---|
| 定位与规模 | 一句定位 + star/采用度(**标实测日期**) | — |
| 意图理解/输入处理:机制、策略与方案 | 决策输入 / 算法或 prompt 整段摘 / 候选集构造 | 1 张 |
| 分发与反馈(核心机制):机制、策略与方案 | 决策落地 + 置信度/校验/重试/拒绝/兜底回路 | 1 张 |
| 整体流程与可借鉴点 | 端到端叙述 + **表态式**「抄什么/戒什么」 | 1 张 |

**深度判据**(标 ★ 的可机检):
- 每个策略决策点四件套:输入 / 算法或 prompt / 数据结构 / **抄自谁**;
- ★ 每对象 **≥3 段真实代码或 prompt 摘录(带 file:line)+ 3 图**;
- 真克隆真读,⛔ 禁 README 定论;仓库重构/迁移必须标注取材 commit/分支;
- **案头线**(现状全景/协议/学术)继承 `s2-research.md` 的三路调研与来源纪律:一手/二手分区、URL 可溯、**绝不编造来源**、降级档显式声明;
- **负面发现显式写「无」**——「N 家里 M 家没有 X」常是最关键结论,不许沉默;
- **承重结论独立复核**:执行摘要引用的每条证据锚点,须第二双眼睛回源码核对(实跑:135 处复核抓出 1 处张冠李戴)。

## 四、报告骨架(模板 `templates/tech-research-report.md`)

```
执行摘要(一句话结论 + 覆盖全维度的核心判断表 + A1 关切各自成节)
→ ①现状全景(案头调研全量并入,⛔ 不许只留在底稿)
→ ②逐对象详解(2.0 总览表 + 2.N 四节)
→ ③横向对比(范式分族 + 关键维度)
→ ④聚焦(A1 要解的问题 → 可落地方案,每个决策点标「抄自谁」)
→ ⑤行业对照(若涉,如手机助手)
→ ⑥方案收敛(蓝图 + 一页决策卡)
→ ⑦复核与诚实边界 → ⑧方法与来源 → 附录(底稿全文;正文引用带附录编号)
```
- **交付覆盖对账**:本次做过的每一路工作 → 交付物哪一节;做了没进交付物 = 缺陷。
- **A1 关切显式成节**:下游用途里的关键词(如「正确性」「置信度」「快」「准」)在执行摘要各有一节或一表,⛔ 不许散在正文里让读者自己捞。

## 五、交付规格

- 载体按 A3;飞书**只用官方 lark-cli**(⛔ 禁第三方 CLI);**正本唯一**,更新用 overwrite 同一文档保链接;
- 全部小节编号、总览表在详解之前、图全部真图内联(视觉判据见 `diagram-standards.md`「视觉质量与受众分层」节);
- ⛔ **报告产物(含配图)不进 git**——只有 skill 更新才进 git。

## 六、并行生产规范前置

多 agent 分工**开始前**先立三件并下发每个工位:①同一份逐对象结构模板 ②图规范 ③口径表(对象数/编号/术语)。
⛔ 规范后置 = 靠终审兜底(实跑:标点不一致/旧口径残留/图风格漂移全部源于规范后置)。

## 七、增量交付节奏

写作执行补充见 `evidence-first-writing.md`：先完成一个对象中相互关联的策略决策点样章，由独立消费者根据正文追溯输入、分支条件、输出与失败回路，检查通过后逐对象分批展开。每批绑定源码版本与具体定位，缺失实现、未运行和负面结果分别表述；代码摘录/配图数量只防缺项，不等于机制解释合格。写作进度放既有 `state.md`，不另造事实账本；采用建议先经产品决定再进 PRD，摘要最后写。

平台增量更新先回读、检测并合并远端编辑，再更新同一正本；未完成部分标进行中。下文 overwrite 只适用于已确认无远端未合并改动的受控镜像，不能覆盖他人新增内容。共享契约的 GUI 条款不适用于本模式，但同版正文、真实图和平台验收仍适用。

- 正本文档**骨架即建**;每完成一大块(如逐对象一批)就更新正本并一句话告知用户「XX 已可看」;
- 用户中途反馈**当轮消化并回写判据**(不是只改那一处)——早看早纠的返工代价小一个量级。

## 八、图(判据正本在 diagram-standards.md,此处只指位)

批量框架图走统一 Mermaid 主题及实际编译器；门面图（执行摘要/方案蓝图，≤20 张）走内置 `modules/diagramming` 的结构源→SVG→PNG 与视觉审查门，不要求额外安装制图 Skill；受众含产品时，方案图**另画产品共读版**（零代码符号）。字号/高度红线/节点数上限见 `diagram-standards.md`「视觉质量与受众分层」。

## 九、出场门禁

```bash
python3 scripts/product-flow-run.py plan --root <项目目录> --mode only --modules research --research-mode tech-approach --write
python3 scripts/tech-research-gate.py --pre  <research_dir>   # 交付前:结构机检
# …推送正本…
python3 scripts/gate-run.py --root <项目目录> scripts/tech-research-gate.py --post <research_dir>
```
- `--pre` 查:小节编号连续;每对象 4 节 + 3 图引用 + ≥3 段带 file:line 摘录;口径数字 ∈ scope.md 声明值∪豁免清单;图文件存在且高度 ≤ 红线。
- `--post` 重新执行本地检查，再对飞书或钉钉做同版本全文比对、逐图上传身份与章节位置核验；关键词存在不能代替全文验收。前检不能计作正式出场结果；其余必跑门以当前计划为准。
- `scope.md` 写 `documentPlatform: feishu` 或 `dingtalk`、`delivery_doc: <正本文档ID>`。`research/review.md` 使用 `templates/research-quality-review.md`；逐对象技术解释与全文章节必须覆盖，不能伪造 GUI 功能账。真实图与源/渲染回执进入 `evidence-manifest.json`。
- 门自身带 `--self-test`(漏编号/缺图/旧口径三类反例必须红)。
- 交付前另跑**语义终审**:独立 agent 通读全文,查矛盾/引用错/术语漂移/承诺未兑现,P0 清零才交付。

## 十、诚实边界

- 本模式产出是**方案判据**,不替代 S3 的取舍拍板;
- 门禁能查结构与口径,查不出「结论对不对」——承重结论的正确性靠独立复核与语义终审,且两者也只能降险不能保真;
- 案头线约不到一手来源时,显式降级声明,⛔ 不拿二手冒充一手。
