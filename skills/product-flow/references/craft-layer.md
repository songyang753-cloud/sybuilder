## 一、构图与栅格（product-flow 此前只有数值，没有构图）

### 1.1 四种栅格，按内容形态选
| 栅格 | 用于 | 判据 |
|---|---|---|
| **列栅格** | 常规页面 | 12 列最通用；列数 × 内容块数要能整除，否则必然出现孤立块 |
| **模块栅格** | 卡片墙、图库、bento | 行列同时约束；模块跨度只用整数倍 |
| **基线栅格** | 长文、编辑型内容 | **所有垂直间距是基线的整数倍**（4 或 8pt） |
| **层级栅格** | 复杂后台 | 分区各有各的栅格，但**共用同一间距阶梯** |

**8pt 栅格为什么是默认**：能被 2/4/8 整除，与 16px 正文、24px 标题天然对齐，主流设计系统都用它。

### 1.2 模块化比例（字阶不是随手定的）
步进比取自音程：`1.125 小二度`（密集后台）· `1.2 小三度`（产品向）· `1.25 大三度`（品牌向）·
`1.333 完全四度`（编辑向）· `1.618 黄金比`（展示/海报）。
⚠️ **一个项目只用一个比例**。混用会让层级读起来"差不多但说不上哪里怪"。

### 1.3 阅读模式决定放什么在哪
- **F 型**（文字密集）：视线沿顶部横扫 → 沿左侧下行 → 再横扫。**重要信息靠左靠上，别指望右下角**
- **Z 型**（视觉页）：左上 → 右上 → 对角 → 左下 → 右下。CTA 放在 Z 的终点
- **中心聚焦**（演示/海报）：全部收拢到中心，边缘留空

### 1.4 三分法与焦点
把画面分九宫，**焦点放在交点上而不是正中**。正中在功能界面里读起来是"没想过"，在海报里读起来是"呆板"。

### 1.5 ⭐ 光学对齐 ≠ 数学对齐
**元素应该对齐到视觉边缘，不是数学边缘。**
- 图标与文字并排：图标常需 `margin-top: 1–2px` 才看起来在一条线上
- 圆形/三角形与方形并排：圆形要**溢出**一点点（overshoot）才等大
- 引号、括号开头的行要**悬挂**到文本块外（`hanging-punctuation: first last`）
- 居中的按钮文字，若右侧有图标，整体要向左偏半个图标宽

⚠️ **这一条不可自动验**。它进报告的形态是「已按 1.5 逐项走查，发现 N 处」。

## 二、排印工艺（visual-spec 1.6 之外还缺的）

```css
/* 光学字号：可变字体按实际字号优化字形，标题与正文不该用同一套字形 */
h1   { font-variation-settings: 'opsz' 48; }
body { font-variation-settings: 'opsz' 16; }

/* 字偶距与连字 */
p { font-kerning: normal; text-rendering: optimizeLegibility; }

/* 悬挂标点：引号挂到文本块外，左边缘才是齐的 */
p { hanging-punctuation: first last; }

/* 孤行寡行：别让最后一行只剩一个词 */
p  { orphans: 2; widows: 2; text-wrap: pretty; }
h1,h2,h3 { text-wrap: balance; }

/* 断词：改善两端对齐，减少"白河" */
p { hyphens: auto; hyphenate-limit-chars: 6 3 2; }
```

⚠️ **中文的差异**：`hyphens` 与 `hanging-punctuation` 对中文意义有限；
中文要管的是**标点挤压**（`text-spacing-trim`）与**避头尾**——行首不许出现 `。，、！？：；」』`，
行尾不许出现 `「『（`。

## 三、色彩科学（此前只有一句"用 OKLCH"）

### 3.1 色彩空间选型（按任务选，不是全用一个）
| 任务 | 用 | 为什么 |
|---|---|---|
| 感知均匀的操作（调亮/调饱和） | **OKLCH** | 明度/彩度/色相三轴都均匀，修好了 CIELAB 的蓝色问题 |
| CSS 渐变 | **OKLCH** / `color-mix(in oklab)` | 不会像 RGB/HSL 那样中段发灰 |
| 取色器 / 色域感知 | **OKHSL / OKHSV** | 像 HSL 一样是柱坐标，但有感知基础 |
| 印刷 | **CIELAB D50** | ICC 标准光源 |
| 跨媒介外观匹配 | **CAM16** | 考虑环境、适应、亮度 |
| 色差（精确） | **CIEDE2000** | 感知距离的金标准 |
| 色差（够用且快） | **OKLAB 欧氏距离** | 大多数场景足够 |

⚠️ **HSL 不是"坏"，是它的三个通道不对应人的感知**——同一 L 值下不同色相的实际明暗差很多。
快速取色可以用，**建色阶不许用**。

### 3.2 建色阶的顺序（不许跳）
1. **用 OKLCH 建感知均匀的色阶**——同一级在所有色相下明度一致，不出现"中段发浑"
2. **建三层令牌图**：参考层（调色板）→ **语义层**（surface / on-surface / accent / success / warning / danger）→ 组件用法
   ⛔ 组件**永远不许直接引用参考层**——那是令牌体系崩塌的起点
3. **明暗两套都验对比度**（WCAG 或 APCA），不是只验浅色

### 3.3 ⭐ 序列色阶的唯一硬判据：感知导数要平
把相邻样本之间的**感知步长**画出来，**应该是一条水平线**——**在彩色和灰度下都是**。
凸起的地方，意味着色阶在那里**夸大了数据里并不存在的变化**。
（这是经典 jet 色图真正的失败原因，不是它"难看"。）
→ 做数据可视化的产品，这条比任何审美判断都重要。

### 3.4 ⛔ 不要用 coolors.co 这类"调色板生成器"
它不生成，它是从一个 7,821 条的预制列表里挑——**你拿到的是别人早就用过的东西**。

## 四、情绪基调 × 强度：两个正交的旋钮

product-flow 原有**强度档位**（克制/标准/丰富/极致），但没有**情绪基调**。
两者正交：可以有"克制的 Trust"，也可以有"丰富的 Trust"。

| 基调 | 用于 | 色 | 字 | 版式 | 动效 |
|---|---|---|---|---|---|
| **Trust 可信** | 金融/医疗/企业 B2B/法务 | 蓝、灰、深紫——冷静稳定 | 衬线体现权威 + 干净无衬线保清晰 | 对称、平衡、大留白 | 微妙、平滑、有目的 |
| **Excitement 兴奋** | 娱乐/游戏/社交/活动 | 高饱和——红橙品红电蓝 | 粗、几何、展示体 | 非对称、动态、重叠、斜线 | 快、有弹性 |
| **Professional 专业** | B2B SaaS/生产力/开发者工具 | 精炼中性 + **单一强调色** | 现代无衬线 + 等宽用于代码 | 栅格化、信息密集但有序 | 功能性、跟手、无装饰 |
| **Creative 创意** | 作品集/agency/文化项目 | 意外的组合、渐变、双色调 | 展示体、可变字体、混排、大字号 | 破格栅格、图层叠压 | 实验性、滚动驱动 |

**用法**：在设计简报里**同时声明基调与档位**（如「Professional × 克制」），
后续每个决定回查这两个词。⚠️ 基调属于**品味轴**（收敛），见 `taste-memory.py`。

## 四之二、⭐⭐ 四个正交旋钮（原来只有一个「语义四档」，把不同的事混在了一起）

| 旋钮 | 控制什么 | 与别的旋钮无关的地方 |
|---|---|---|
| **情绪基调** Tone | Trust / Excitement / Professional / Creative | 与"多冒险""多密集"无关 |
| **创作振幅** Variance 1–10 | **布局风险**：对称栅格 → 分栏 → 非对称偏移 → 动力学排版 | 与"装多少内容"无关 |
| **信息密度** Density 1–10 | 一屏装多少 | 密集也可以很大胆，宽松也可以很保守 |
| **精细度** Craft Level 1–10 | 打磨到什么程度（收尾跑几道 pass） | 与风格无关，只与工时有关 |

### Variance 的档位含义与默认值
| 档 | 产品界面 | 营销页 |
|---|---|---|
| 1–3 | 对称栅格、安全层级 | 居中 hero **只在有非对称支撑时**才可接受 |
| 4–6 | 分栏布局、指标层级、**一处布局破格** | 分栏/bento hero、交替特性行 |
| 7–8 | 外壳里的强排版时刻（空态、首次引导） | 非对称偏移、滚动联动、展示字号的戏剧性 |
| 9–10 | **罕见**，只允许一处实验性外壳时刻 | 动力学排版、滚动编排——**需明确授权** |

**没指定时的默认**：仪表盘/设置/认证/表格 **4** · 落地页（已上线产品）**7** ·
落地页（预约/未发布）**6** · 作品集/案例/发布会 **8**。

## 四之三、⭐⭐⭐ 当代的默认坍缩（比紫渐变高一层，也更难自察）

反 slop 的黑名单（紫渐变、三列图标网格、居中一切）**已经被广泛学会规避**。
于是生成式设计坍缩到了下一层——**三个"看起来很有品味"的默认**：

| # | 坍缩形态 | 长什么样 |
|---|---|---|
| 1 | **暖奶油 + 衬线 + 陶土** | 底色约 `#F4F1EA`，衬线展示体，陶土/黄铜强调色 |
| 2 | **近黑 + 一个酸色** | 近黑底 + 一个亮酸绿或朱红强调色 |
| 3 | **大报版式** | 发丝分隔线、零圆角、密集分栏 |

同类还有：紫色网格渐变 · 对称三图标卡 hero · 全黑侧栏 · **无理由的 Inter 打天下**。

⛔ **每一个都只在简报明确要求时才合法，绝不能作为「没有品牌方向」的默认答案。**

### ⭐ 二阶反射检查（这条比 similar-prompt 自测更深一层）

> 「devtool → 深色 + 等宽」是**第一反射**。
> 「不想紫的 AI 工具 → 编辑感衬线 + 克制」是**同一个反射，只是深了一层**。

**做法**：先给这一版的美学**命名一条赛道**（"编辑感排版" / "终端深色 devtool" / "暖手作"），
然后问：**光看品类，能不能猜出这条赛道？**
能猜出来 → **重做，直到猜不出来**。
⭐ **赛道应该由这个品牌的具体之处挑出来，不是由品类挑出来。**

**自测**：*同品类的另一个品牌、同样的简报，会不会产出同一个方案？*
任何一个维度上答"会"，那个维度就是**反射，不是决定**——改掉它，并写清改了什么。

## 四之四、签名赌注：只下一个，且在建造时就建

**每一个界面交付物恰好带一个值得记住的决定**，在计划阶段选定、**在建造那一步就做出来**，
⛔ **不许推迟到"打磨"阶段**——推迟的签名 99% 不会发生。

**产品界面（选一个）**
1. 与业务相关的自定义空态图形（简单 SVG）
2. 有辨识度的导航选中指示（左侧竖条 / 药丸 / 圆点）——**全系统统一**
3. 首次运行面板——可关闭、讲价值不讲功能
4. **主表格**行 hover 的轻微抬起 + 阴影（**只在主表格上**）
5. 命令面板或 `⌘K` 键位提示（当搜索/操作确实值得时）

**认证界面（选一个）**
1. 面板佐证资产——一个可信的指标 + 迷你走势图 **或** 一句署名引述（**不要两者都有**）
2. 信任页脚——合规/数据驻留写在面板底部的三级文字里
3. 与业务相关的欢迎句——用产品自己的动词（"接着上次继续"），不是通用填充
4. SSO 行上的**真实**服务商标识——等重中性描边，不要假图标
5. 面板上一处克制的图形母题

**营销界面（选一个）**
1. Hero 裁切——产品视觉在首屏边缘处被切断
2. 浮在截图上的佐证卡（指标、通知）
3. 自定义章节标记（编号标签、业务图标母题）
4. 有辨识度的 CTA 文案——**具体动词，不是"立即开始"**
5. 一处滚动时刻（logo 带或克制的标题入场，variance ≥7）

## 五、⭐⭐ Delight：眼前一亮的可证伪定义

> **Delight is specificity, not decoration.**
> 目标是**一两个用户会截图的瞬间**——不是彩带，不是弹跳，不是 emoji。

### 5.1 四类候选，按安全性排序（从上往下加）
1. **文案具体性**（最安全）——确认 Toast 要**点名那个东西**：
   「已邀请 3 人：张三、李四、王五」而不是「邀请已发送」。
   空态要有分寸的机智：「还没有项目——添加第一个」优于「哎呀，这里空空如也 😅」
2. **Hover 编排**——多属性（位移+颜色+阴影）**共用同一时长与缓动**一起动。**一张卡，不是每张卡**
3. **状态转场**——乐观更新 + 极小的成功微动效（对勾描边、数字滚动、更新行轻微缩放落位）
4. **一个签名细节**（最冒险）——与业务相关的自定义列表符号、某一节的非对称偏移、
   **追踪真实进度的滚动指示**（阅读进度、表单完成度）

### 5.2 按动效强度门控（不许越级）
- **≤3**：只做文案（候选 1）。**不做任何动画式 delight**
- **4–7**：文案 + hover + 状态转场（候选 1–3）
- **8+**：四类全开，含签名细节

### 5.3 ⛔ 永不添加
弹跳缓动 `cubic-bezier(0.68,-0.55,0.27,1.55)` · 平凡操作放彩带（保存文件、改字段）·
emoji 刷屏与「🎉 成功！」· **没有在等待任何东西的元素上做 idle 浮动/呼吸/流光**

### 5.4 必须交出「我选择不做的候选及理由」
与「被否决的动效」同一条纪律：**没有被否决清单，就说明没跑过闸门。**

## 六、旋钮怎么动一档（原来只有档位，没有操作手册）

### 6.1 变响（bolder）——**这是振幅，不是装饰**
按顺序做：① 更新一行 Craft Read（说清什么变了）② 视觉丰富度 +1~2（上限 10）
③ 动效强度 +1（若 <8），**只在焦点元素上**加一处入场或 hover 编排
④ 排版：展示字重或字号进一档、标题收紧字距、数字保持 `tabular-nums`
⑤ 强调色：强化焦点位置的强调色，**绝不加第二个强调色相**
⑥ 签名：把那一个签名赌注加上或加强

⚠️ 已在 9 档以上时，**改为加强签名与排版**，不要继续推档位。

### 6.2 变静（quieter）——**降振幅但不掏空层级。Calm ≠ boring**
① 更新 Craft Read ② 丰富度 −1~2（下限 2），把实验性布局收回清晰节奏
③ 动效 −1~2（下限 2），**去掉滚动揭示与错峰，只留 hover/focus**
④ 视觉重量：展示字号降一档、阴影减到发丝或环境级、减少带边框的容器
⑤ 颜色：强调色位置收到最少、中性化装饰性色调、不加新色相
⑥ 砍装饰性动效：idle 动画、视差、没有职责的浮动元素

**必须保住**：主层级、单一 CTA 级别、无障碍、各状态；签名细节只在它承载意义时保留。

## 七、视觉锚点配方要取什么（原来只说「选一个锚，不要东拼西凑」）

一个合格的锚点配方包含七块，**取的时候七块一起取，不是只取色板**：

| 块 | 例（Linear） |
|---|---|
| 流派 / 气质 / 适用 / 触石 | Modern Tool；「开发者工具的安静奢华」；linear.app |
| **调色板（带角色与占比）** | 底 `#08090A`（**暖调近黑，不是纯黑**）· 强调紫 `#5E6AD2`「**用在 <5% 的像素上**」 |
| **排版（带反默认）** | Inter Tight 600——「**绝不用默认字重的 Inter，那是 AI 默认长相**」 |
| 间距 / 圆角（带性格与硬上限） | 圆角 6/12/16，**绝不超过 16**；性格是「克制、精确、不软糯」 |
| 阴影 / 动效（带具体曲线） | 阴影「几乎没有」；**绝不发光、绝不彩色阴影**；`cubic-bezier(0.22,1,0.36,1)` |
| ⭐ **签名动作**（眼前一亮的来源） | 发丝级 1px 边框无处不在 · 键盘快捷键 chip · 极克制的 hero 渐变网格（**不是 AI 那种亮紫粉蓝**） |
| ⭐ **Avoid + Don't use when**（诚实边界） | 避免 emoji/弹跳/第二个饱和色；**当品牌是消费向、需要温度、受众非技术时不要用它** |

⭐ **判据**：如果你说不出这个锚点的**签名动作**和**它什么时候不适用**，你就没有真的用它当锚，
只是抄了个色板。

## 八、⭐⭐ 构图层的 AI slop（反 slop 此前只到元素层）

`ai-slop-gate` 查的是**元素级**签名（紫渐变、三列网格、彩色圆圈图标）。
**构图层的坍缩更隐蔽，也更致命。**

📌 **实测证据**：某工具在无提示的情况下盲跑 10 次，**10 次全部产出「左文右图」的首屏**，
跨两个不相关的产品；而 18 个真实参考落地页里**只有 3 个**用这个构图。

> **它什么都适合，是因为它什么都没承诺。**

### 三条做法
1. **抽签，不要挑选**。首屏构图从候选类里**抽**一个，而不是"选一个最合适的"——
   "最合适"就是模型的默认，而默认就是坍缩。
   ⚠️ 抽签的对象是**先按产品命题筛过的候选类**（不适配的类先剔除、写一句为什么）——
   洞察定候选，抽签只治「挑选必回默认」的坍缩，不是拿产品去撞运气。
2. **说出这个构图要求的牺牲**。每个构图类都要求放弃点什么，**把那个牺牲说出来**——
   那个牺牲正是让这一页看起来像它自己的东西。
3. **记账**：把本次用掉的构图类记进档案，下一次不许重复
   （与 `taste-memory.py` 的执行轴日志同构，用 `--layout` 记）。

### ⭐ similar-prompt 自测（眼前一亮的可证伪判据）
> **把这一页的品牌换成同品类的另一个品牌，它还能照样用吗？**
> **能 → 签名不够强。** 在交付前加强它，不要在评审时才被问。

## 九、运行时/后台界面的专项反模式（anti-tells）

通用反 slop 之外，功能型界面另有一批：

- ⛔ 不要把**执行页做成营销 hero**
- ⛔ 需要真实日志流或状态表时，**不要用装饰性的假终端**
- ⛔ Retry / Cancel / Copy / Export **不要脱离 run 上下文**
- ⛔ 不要给每条日志、每个时间线步骤都套超大卡片
- ⛔ 不要用装饰容器**稀释** JSON / trace / log 这类调试信息
- ⛔ 操作型仪表盘需要扫描效率时，**不要做得过度空旷**
- ⛔ 不要把无关指标做成完全同质的卡片阵列
- ⛔ **不要用 glow 替代明确的状态、严重程度、focus 或层级**
- ⛔ 不要在页面中途随机切换深浅 surface
- ⛔ 同一语义角色不要重复发明 input / button / badge / row 样式
