# 格式边界：md ↔ 飞书 / Figma / HTML

> **本流水线的中间格式是 md，而三个终点分别是飞书文档、Figma、HTML。**
> 这份文件回答一个具体问题：**md「只有内容没有格式」，会丢什么、会留下什么。**
>
> 结论先行：**md 不够富不是主要问题，md 没有身份才是。**
> 真正会造成不可恢复损失的，不是「表格没有合并单元格」，而是
> **「远端被别人改了，而本地不知道，下一次覆写把它抹掉」**。
> 前者难看，后者是删掉别人的工作。

---

## 〇之一、⭐⭐⭐ 消费侧边界：**一份 md 能证明什么、不能证明什么**

上面两节管的是**写入侧**（md 出去会丢什么）。这一节管**读取侧**：
下游拿到一份 md，它到底算不算「读过原件了」。⛔ **答案通常是不算。**

| md 可以做 | md ⛔ 不可以做 |
|---|---|
| 描述 SOP、条件、责任、停止线 | 当 Figma 视觉的替代品 |
| 记录研究分析、决策理由、假设、风险 | 当 HTML 动态行为的替代品 |
| 保存 delta、handoff、人工评审结论 | 成为飞书已批准 PRD 的**第二个可编辑版本** |
| 索引原件的 URI/版本/锚点 | 只凭一个链接就宣称「已读取/已验收原件」 |
| 展示由机器契约生成的**只读投影** | 手抄 copy/state/flow/token 精确事实（＝造第二个源） |
| 外部系统不可用时作**候选稿/受控镜像** | 在无法原生回读时冒充最终交付或三方冻结证据 |

**四条硬规则**（G7.5 三查与各阶段出场共同依赖）：

1. **md 摘要不得作为下一阶段的唯一输入**——下游必须读它这一步真正依赖的那个原件。
2. **截图 vs 结构元数据，两者互不替代**：截图只证明某一刻的外观，证明不了 Figma 可编辑结构；
   node 元数据只证明结构，证明不了画面好不好——**两个都要，缺一只给有限结论**。
3. **HTML 截图证明不了可达性**：状态、焦点、键盘、恢复必须**真的运行并回放**。
4. **飞书导出的 md 只是受控镜像**：没有远端 revision + 回读，它证明不了自己仍是当前批准版。
   ⚠️ 任务若只要求 md 草案，交 md 合法——但**不得标成飞书/Figma/HTML 原生交付完成**。

## 〇之二、⭐⭐ 还有一条边界：**md → md**（阶段之间）

本文件原本只管 **md → 远端**（飞书/Figma/HTML）。
但全链 review 发现：**大量中间产物在阶段之间也是靠 md 传递的**，
而那条边界**此前零机制**——S2 的机会、S3 的定义 18 项，怎么流进 PRD 的，没人核。

### md→md 的三种衰减（危害递增）

| # | 形态 | 长什么样 | 为什么难发现 |
|---|---|---|---|
| ① | **丢项** | 上游 N 条，下游只承接 M 条 | 下游文档**自身是完整通顺的**，看不出少了什么 |
| ② | **改写漂移** | 下游用自己的话复述上游，语义悄悄变了 | 两边分开读都对，并排读才发现不是一件事 |
| ③ | ⭐ **静默降级** | 上游「必须」→ 下游「建议」；上游 `P95 ≤ 300ms` → 下游「响应要快」 | **最隐蔽**——下游读起来完全通顺，而约束已经没了 |

### 守法
1. **双向条目对账**：每条上游条目要么被承接，要么**显式标「不承接 + 理由」**。
   ⛔ **沉默地丢掉不是结论。**（`chain-gate.py` G0/G0.5/G0.8）
2. **关键条目引用而不复述**：带出处锚点（`[定义 §11]`、`OPP-03`），
   ⭐ **ID 贯穿链（M1）在这里的作用就是防漂移**——引用 ID 不会漂，复述文本会。
3. **量化与约束级别不许降级**：机器可查——
   上游那节有数字而下游对应节没有 = 降级；上游 MUST 下游 SHOULD = 降级。
4. **上游输入映射表**：下游文档要有「我吃了谁」的表（PRD 附件 H.0），
   与「我喂给谁」（H.1）**成对存在**。只有单向映射的文档，另一半永远没人核。

📌 **为什么模糊文本匹配不行**：对账门首版用「机会文本的前 8 个字是否出现在下游」做匹配——
「让批量失败可逐条撤销」与下游的「批量失败可逐条撤销」**只差一个字就漏判**。
**模糊匹配既会漏也会误，而且漏的时候悄无声息。** 对账一律走 ID。

## 〇之三、⭐⭐ 五张「对账用表」的边界（2026-08-31 补，全链 review 揪出）

这六张表是**机器对账的键**，不是给人读的内容。**它们过边界时的规则和正文不一样**：

| 表 | 产出在 | 谁消费 | 过边界会丢什么 | 守法 |
|---|---|---|---|---|
| **证据等级表** | `definition-final.md` | `state.md` 停止线 · S7/S8 入场 · S10 假设账 | **飞书表格会把 `E0` 之类当普通文本**，复制时容易漏行 | ⛔ **停止线那一列必须原样抄进 `state.md`**，不许复述 |
| **原子功能账本** | `atomic-feature-ledger.md` | PRD · Figma · HTML | 飞书宽表会静默压列；分表后也可能漏掉某些 `AF-xxx` | `AF×COMP` 长表作唯一事实正本；横向面板只拆竞品列，复用相同 AF 行集；写后回读核列数、AF 行集和竞品并集 |
| **竞品功能遍历账** | 各深挖竞品档案 `#功能遍历覆盖账` | 原子功能账本 · 功能调研飞书报告 | 先凭已有认知列 AF 会漏掉竞品独有入口、角色/档位差异和失败恢复 | 每个 `SURF-xxx` 处置为 AF/NON-FEATURE/BLOCKED；`FULL/PARTIAL` 反查同竞品同实测 RUN；写后回读核 SURF 行数、处置列和 AF 反查 |

| **元素标识表** | `interaction-spec.md` | HTML `id` · Figma 图层名 · 用例选择器 | 同上 | ⛔ 同上 |
| **技术债登记 K.6** | PRD 附件 K.6 | S10 技术债结算 | 迁到飞书后**没人再回头看** | 还款条件写成**日期或可判定条件**，不是「以后」 |
| **单向门清单** | `definition-final.md` + 视角 11 | PRD 5.6 · S5 入场 | —— | 未拍板的行**必须挡住下一阶段** |

⭐⭐ **共同点：这六张表的价值全在「字符逐字相同」上。**
⚠️ **正文允许改写，这五张表不允许**——
改写正文只是漂移，改写这些表**会让对账门整片失效，而且它们会安静地报绿**
（找不到就是「没有这一项」，不是「对不上」）。

⛔ **过边界后必须回读校验**：`doc-sync-guard.py` 比指纹，
而这五张表还要**逐行比 slug 集合**——数量对不上就是丢了行。

## 一、三类丢失（按危害排序，不按显眼程度排序）

| 类 | 方向 | 表现 | 危害 | 守它的东西 |
|---|---|---|---|---|
| **① 写出去丢** | md → 远端 | 表格被静默压列 · `write` 返回 success 而内容缺一大块 · 图片插错位置 | 高：**看起来成功了** | `doc-sync-guard.py check --readback` |
| **② 读不回来** | 远端 → md | **别人在飞书里改了，本地副本不知道，下次覆写抹掉** | **最高：不可恢复，且丢的是别人的工作** | `doc-sync-guard.py` 的远端指纹 |
| **③ 表达不了** | md 本身没有这个维度 | 组件变体矩阵 / AutoLayout / 原型连线 / 焦点顺序 / 动效实际观感 | 中：会被下游「自己发挥」补上，而那部分不在任何需求文档里（＝ M4 的反向漏） | 契约 + 对账门 + 人工走查 |

## 二、逐个边界：丢什么、留什么、怎么守

### 2.1 md → 飞书 / 钉钉文档（PRD 的终点）

**丢**
- **多列表格静默压列**：4 列落地成 2 列，而 `blocks_added` 数字正常、返回 `success`
- **`write` 静默失败**：内容缺一大块却不报错（实测同一份输入，第一次丢了 24 张表，重写一次就对）
- **callout / 折叠块 / 分栏 / 状态标签 / @人**：md 里没有对应物；**全文覆写会把它们连同已上传的图片一起清掉**
- **动态目录**：`[TOC]` 在飞书里只会变成一行普通文字（已实测），目录必须由人插一次
- **图片位置**：靠偏移推算，而**偏移在同一篇文档内会漂移**（实测同一篇 PRD 图表段 −2、功能段 −8）

**留下（遗留物，比丢失更隐蔽）**
- 上一版的图片、空占位块、被覆写切碎的 callout 残片
- **删除操作的连带伤害**：`upload-image --index N` 后删 `N+1`，占位不存在时 `N+1` 就是紧随其后的表格
  📌 真实事故：**25 张表被删光**，而图片位置校验全绿——**盯着图去验永远发现不了**

**守法（照做，不许省）**
1. **源 markdown 里根本不要写 `![](…)`** —— 不产生占位就不需要删除，全程零删除
2. 写入前 `doc-sync-guard.py record <file.md> --url <链接> --kind feishu`
3. 写入后**必须回读**，再 `doc-sync-guard.py check <file.md> --readback <回读文件>`
   它逐张核**每张表的列数**、核标题集合、核图片数——**这三样正好是三种静默失败的指纹**
4. 图片用**探针法**：先插一张 → 回读确认落点 → 按实测偏移批量。**不许全文套一个推算值**
5. 链接一旦发出去就**原地更新**，不新建文档换链接
6. 竞品横向矩阵超过 3–4 个竞品列时，按竞品列拆成多个面板；每个面板固定保留
   `AF-ID + 原子定义 + 我们/目标`，并复用完整 AF 行集。回读必须核“所有面板 AF 行集相等”与“正式竞品列并集完整”。
7. 竞品档案的功能遍历覆盖账不得只在飞书报告内保留；受控镜像逐行保存 `SURF-ID/RUN/表面/最小动作/处置/实测状态/证据/阻断`，回读后再生成飞书中的覆盖摘要。

⚠️ **判据不是「有没有报错」，是「结构指纹一不一致」。** 写入返回成功不等于内容进去了。

### 2.2 远端 → md（**此前完全没有机制的一侧**）

链接发出去之后，**别人会直接在飞书里改**。而本地 `prd/` 只是「可 diff 的副本」。

**这不是格式问题，是内容问题**：本地覆写会静默删掉别人的修改，且**不可恢复**——
飞书有版本历史，但没人知道要去翻，因为**没有任何东西报错**。

**守法**：`doc-sync-guard.py` 在 sidecar 里存「上次回读到的远端指纹」。
下次 `check --readback` 时若发现 **本地未动而远端指纹变了** → 判定「远端被别人改过」→ **红，禁止覆写**。
处置顺序固定：**先把远端改动读下来合并进本地，再推**。

⚠️ 本地与远端**都**变了时，工具只报「需要人工合并」，**不替你选一边**。

### 2.3 md → Figma（设计稿的终点）

**表达不了的（md 里根本没有这个维度）**
- 组件变体矩阵（`type × state × size` 的组合与 30 上限）
- AutoLayout 的 hug / fill、constraints、`resize()` 与 sizingMode 的先后顺序
- 原型连线、Dev Mode 标注、变量的 `scopes` 与 code syntax
- **附件 K 的组件规格表只能写像素值**，写不出「这个按钮在窄容器里怎么伸缩」

→ 后果：这些必然由人在 Figma 里补，**而补的那部分不在任何文档里** = M4 的反向漏。

**守法**：把「md 表达不了的」显式登记，而不是假装它不存在。
- 附件 K.3 组件规格表增加**「伸缩行为」**一列（hug / fill / fixed），这是 md 能表达的那部分
- 其余（原型连线、Dev Mode 标注）在 K.4 标注为「**Figma 侧独有，md 不承载**」，
  并在 S7 出场条件里由 `figma-editability-gate.py --strict` 兜底——
  它查的是**结构是否可维护**，正好是 md 表达不了的那一层

**会失效的东西：node-id**
- **node-id 在 Figma 里重排 / 重建后会失效**，而链接看起来完好，点进去是空的或是别的东西
- **守法：双锚。** 第四章的设计稿链接必须同时带 **node-id** 与 **图层名**（`F-01/pc/empty`——⛔ **状态段用英文 slug**，写「空态」会让 G3 三元键对账失配）。
  node-id 用于直达，图层名是语义锚——**重建后能重新解析出新的 node-id**。
- 由 `doc-sync-guard.py figma-anchors <PRD.md>` 校验

### 2.4 md → HTML（交互稿的终点）

**表达不了的**
- 焦点顺序、滚动位置恢复、hover 延迟、`reduced-motion` 降级**后的实际观感**
- `interaction-spec.md` 里第 6 列写的是「降级后的样子」的**文字描述**，HTML 里是代码——**两者一致性无工具可核**

**守法**
- **锚点契约**（`reconcile-gate.py` G2 依赖它）：每个场景一个容器
  `<section data-scene="f01-pc-empty" data-fr="FR-011,AC-1">`
  不演示的在 `<!--不演示 FR-012 理由:纯后端计时-->` 里显式登记
- 动效与降级**只能人工在真实渲染环境里看**，报告写「已走查，发现 N 处」，**不许写 ✅**
  📌 读代码看不出来，截图也看不出来——`var(--x)px` 静默失效那次，画面「看起来正常」、控制台干净，
  是靠一条**量几何的断言**才抓到的

## 三、总的解法：不要把富格式塞进 md，塞进 sidecar

**md 保持可 diff（这是它作为中间格式的全部价值，不能牺牲）。**
格式与身份信息放到同名 sidecar `<文件>.sync.json`：

```
prd/PRD-v2.md              ← 内容，可 diff，进 git
prd/PRD-v2.md.sync.json    ← 身份 + 结构指纹 + 远端指纹，机器可读，进 git
```

sidecar 记：远端 kind / url / 推送时间 / 本地结构指纹（标题集合·表数·**每张表列数**·图数）/ **上次回读到的远端指纹**。

于是三件事同时成立：
1. **内容仍然可 diff**（md 没被污染）
2. **格式约束机器可读**（列数是契约，不是希望）
3. **远端漂移看得见**（本地未动而远端变了 = 红）

## 四、诚实边界

- 本文件解决的是**结构层**的丢失：表、标题、图、链接、锚点。
- **解决不了语义层**：飞书里别人加的一句「这里要改」、Figma 里设计师调的 2px、
  HTML 里的实际手感——**这些只能靠人看**，工具能做的只是告诉你「这里变过」。
- `doc-sync-guard.py` 的 `check` **不带 `--readback` 时只校验了本地**。
  它会显式打印「未校验远端」——**那不是通过**。
- 一句话：**工具能守住「有没有变」，守不住「变得对不对」。** 后者归评审与人工走查。
