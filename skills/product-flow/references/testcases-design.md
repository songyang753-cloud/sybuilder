# 用例设计方法

**目标不是数量，是覆盖。** 20 条互相重复的用例不如 8 条各覆盖一类风险的。

## 七类必做

### 1. 等价类

把输入域切成"行为相同"的组，每组取一个代表。

手机号字段（规格：11 位、数字、1 开头）→ 有效类：测试运行时构造 `'1' + '0' * 10`（合成输入，不是真人号码）；无效类：空 / 10 位 / 12 位 / 含字母 / 2 开头。
⚠️ **等价类的边界靠 PRD 的规格划，不靠常识划**。规格没写"1 开头"就不许假设它必须 1 开头——那是缺口，不是让我补。

### 2. 边界值

每个数值/长度约束取 `min-1 / min / min+1 / max-1 / max / max+1`。
📌 缺陷密集区。「5 次锁定」要测第 4 次不锁、第 5 次锁——只测"错很多次会锁"等于没测。

### 3. 状态迁移

对有状态的功能画迁移表，覆盖每条合法迁移与关键非法迁移。

| 当前态 | 事件 | 目标态 | 用例 |
|---|---|---|---|
| 正常 | 连错 5 次 | 锁定 | TC-011-1 |
| 锁定 | 输入正确密码 | 锁定（不放行） | TC-011-3 |
| 锁定 | 等待 15 分钟 | 正常 | TC-011-4 |

⚠️ **非法迁移最容易漏**：锁定期内输对密码仍应拒绝——这条不测，线上就是个绕过。

### 4. 异常路径

网络失败 / 超时 / 空数据 / 无权限 / 并发冲突 / 重复提交 / 中断恢复。
⚠️ 预期结果必须来自 PRD 的异常场景表。PRD 没写就是 R3 缺口，**不许自己定"应该提示网络错误"**。

### 5. 权限矩阵

角色 × 操作画矩阵，每格填允许/拒绝，逐格出用例（拒绝格同样要测）。
⚠️ 只测"有权限的人能做"是半套；**越权测试测的是"没权限的人做不了"**。

### 6. 组合爆炸时用 pairwise（成对组合覆盖）

多参数功能（浏览器 × 系统 × 权限 × 套餐 × 支付方式…）穷举不可行时，用**成对组合**：保证任意两个参数的取值组合都至少出现一次。依据是多数缺陷由**两因素交互**触发。

建模两段式（参数 + 约束）：
```
# Parameters
Browser:  Chrome, Firefox, Safari
OS:       Windows, macOS, Linux
Plan:     Free, Pro, Team

# Constraints —— 用来剪掉业务上不可能的组合
IF [OS] = "Linux" THEN [Browser] <> "Safari";
```
取值仍按前面的方法选：**等价类 + 边界 + 负例**，不是随便列几个。

⚠️ **何时不该用 pairwise**：
- 组合空间本来就小到能穷举 → 直接穷举，别引入近似。
- **缺陷需要三个以上参数同时交互才触发** → 成对覆盖保证不到，会漏。安全攸关逻辑要提高覆盖强度或全枚举。
- ⚠️ **约束写错会静默生成不可能的行**（Safari on Linux），而生成器不会报错——**约束必须逐条写明「为什么存在」，并验证它真的剪掉了目标组合**。

⚠️ 期望输出必须写具体：**「登录成功，跳转到工作台」**，不许写「正常」「可用」「Works」。

（来源：`omkamal/pypict-claude-skill`，基于 Microsoft PICT，2026-08-16 查证。本机未安装该工具，**手工建模同样成立**；若要跑工具再单独装，不作硬依赖。）

### 7. 安全用例（最容易整类缺失的一类）

前六类都在测「功能对不对」，这一类测「**能不能被滥用**」。差别在于：功能用例假设用户按设计操作，安全用例假设对方**故意不按**。

| 类型 | 测什么 | 依据来自 |
|---|---|---|
| **越权（对象级）** | 用 A 的身份去读/改/删 B 的数据，直接改 URL 或请求体里的 ID | PRD 附件 C.2 权限矩阵的每个 ❌ |
| **越权（功能级）** | 低权限角色调用高权限接口 | 同上 |
| **注入** | 输入含 SQL/命令/模板语法的字符串 | 工程基线（`s9-quality-gates.md` SEC-3） |
| **XSS** | 输入含脚本标签，在展示处是否被转义 | 工程基线 SEC-4 |
| **敏感信息泄露** | 错误提示是否暴露内部信息；列表接口是否返回了不该给的字段 | 错误提示 → 工程基线 SEC-8；列表多余字段 → **SEC-6 对象级授权**；产品级脱敏程度 → **附件 C.6** |
| **限流** | 高频重复调用（登录、验证码、导出）是否被限制 | 工程基线 SEC-7（⛔ 限流不写进 PRD——见 prd-complete 附件 C 尾注；按档位的业务配额才进 C.6） |
| **文件上传** | 超大文件、伪装扩展名、路径穿越文件名 | 工程基线 SEC-2（输入校验——上传面已在其判据里点名） |
| **重放与幂等** | 同一请求提交两次（尤其支付、扣减、审批） | **附件 C.6**（重放与幂等要求） |

⚠️ **两条依据来源要分清**（对应 `s9-quality-gates.md` §一的双轨制）：
- **工程基线类**（注入/XSS/限流/泄露）：**不需要 PRD 授权也要测**，它们是工程标准，PRD 没写不构成豁免。
- **产品级规则类**（谁能看谁的数据、导出要不要审批、脱敏到什么程度）：**必须有 PRD 附件 C 依据**。没有 → 登记 GAP 回 S4，**不许自己决定权限模型**。

⚠️ **越权用例必须写清"用谁的身份、动谁的数据"**：「测试越权访问」不是用例；「用成员 A 的凭据请求成员 B 的文件详情接口，预期 403 且响应体不含任何业务字段」才是。

## 优先级

| 级 | 判据 |
|---|---|
| P0 | 核心路径 + 数据安全 + 权限 + 会造成不可逆后果的 |
| P1 | 主要功能的异常分支 |
| P2 | 边界与极值 |
| P3 | 提示文案、样式类 |

## 用例质量自查

- [ ] 有 `所属 FR/AC`，能反查
- [ ] 前置条件写得出（写不出说明 R7 缺）
- [ ] 步骤可被另一个人独立执行，无歧义
- [ ] **预期结果能在 PRD 里找到原句出处**
- [ ] 不含「应该」「合理」「正常情况下」等无判据词
- [ ] 一条用例只验一件事（一条验三件，失败时不知道哪件坏了）

## 反面例子

```markdown
### ❌ TC-999　登录功能测试
步骤：输入账号密码登录
预期：登录成功，界面正常显示
```
问题：没有所属需求；「账号密码」未指定具体值；「界面正常显示」无判据；一条盖了整个功能。这种用例执行完，你不知道任何事。

```markdown
### ✅ TC-011-1　所属 FR-011 · AC-1
**标题**：连续输错 5 次触发锁定
**前置**：存在正常账号 A，当前失败计数 0
**步骤**：1. 用 A 连续输错密码 4 次　2. 第 5 次再输错
**预期**：第 4 次后仍可继续尝试；第 5 次后锁定，提示「账号已锁定，请 15 分钟后重试」
**依据**：附件A FR-011 AC-1（原文：连续失败 5 次锁定 15 分钟）
```
