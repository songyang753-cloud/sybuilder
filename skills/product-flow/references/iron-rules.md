1. 阶段不可跳序；跳序则 ID 链断，所有对账失效。
2. 编号只增不改，取消的功能标 `[已取消]` 保留编号。
3. 每个事实必须可归到三来源之一，**没有第四种**。
4. 视角表未跑满一遍不得宣告收敛；收敛需连续两大轮零结构性发现。
5. 阶段交接必过对账门，正向漏与反向漏同等对待。
6. 没真跑的记 SKIPPED，不并进通过率。
7. Open Item 四要素缺一即视为未修。
8. 工具的发现可采信，沉默不可采信。
9. **人拍板的五处不得代劳**：S3 定义收敛、S4/S5 终审、S6 demo 锁定、S7 定稿、S8 上线与不可逆操作。
10. 证据必须新鲜、跨轮不同、可独立复核。
11. 逃逸缺陷必须回流 `lessons.md`，不回流视为该阶段未完成。
12. **变更不重写整份 PRD**：先填附件 I.1 影响判断表逐章过 → 只改标「是」的章节 → 正文就地标 `（YYMMDD 变更）` → 废弃进 I.2 → **影响摘要就在文档顶部告警**。**沉默地改掉摘要是最危险的行为**——决策者会以为自己批准的还是原来那件事。
13. **停滞检测**：同一份产物连续 3 轮修改无实质变化时，主动问「**有没有内容可以删掉而不损失重要信息**」。文档不再变好，通常意味着它已经太长了，不是已经完美了。
14. **不许输出「我已尽量精简」这类免责声明**——那不是交付，是推卸。长度不是勤奋的证明；但**该有的不能省**：更新记录、负责人、边界条件、异常场景，是研发和测试真正要用的。
15. **全流程有四十五道确定性门禁 + 五个专项扫描**（清单见 `references/design-quality-gates.md`）：
    令牌来源 · 反 slop 机械层 · 视觉正面判据 · 交互反模式 · **设计意图（方向评估+RISK 提案制）** ·
    Figma 可编辑性 · **跨产物对账 G1/G2/G3** · **元门禁（声称 vs 实际）** · **S2 研究出场**，
    **链路前段对账 G0/G0.5/G0.8** · **产品定义（覆盖下游 18 项）** · **需求质量（含糊词/术语漂移/近重复）**，外加 `sec-scan`（安全基线）· `doc-sync-guard`（格式边界）·
    **`browser-audit.mjs`（浏览器档视觉审计）**· **`taste-memory.py`（品味/执行两轴）**。
    **全绿 ≠ 合格**——它们只覆盖「可维护性 + 来源可追 + 无机械破绽 + 交接不失真 + 文档自洽」，
    好不好看、对不对、值不值得做，归评审视角。
16. **反 AI-slop 必须三层齐上**：门禁（机械）· 评审视角 10（判断）· 生成期约束
    （Design Read / memorable-thing / **三方向登记 + SAFE-RISK 提案制，0 突破须写理由**）。
    **只做门禁那层等于没做**；**RISK 走提案制：零突破合法但必须写理由——没有理由的零 RISK 强烈提示模板货**。
    ⭐ **跨代要求分两轴，方向相反**（`taste-memory.py`）：**品味轴收敛**（明暗/档位/字体气质/
    色温/密度/动效——与用户档案一致，偏离要写理由）· **执行轴发散**（具体字体族/强调色/锚点/布局——
    Greenfield/Overhaul 不许复用上代；**Preserve 反过来必须保持**）。
    判据只有一条：**换掉它，用户会说「这不是我要的方向」还是「这个也行，甚至更好」？**
    ⛔ **品味档案是偏置不是判据**——做成硬门禁会让品味固化，**而固化的品味就是 slop**。
17. **设计评审必须先分类，再用对应的那套规则**（`design-rulesets.md`）：
    落地页 / 应用 UI / 混合，**三者的正确答案互相冲突**——
    落地页要**被记住**（强锚点、有表达力的排版、2–3 处动效），
    应用 UI 要**被忘记**（安静、密集、少颜色、卡片只在它就是交互时才出现）。
    拿错规则集去评，等于没评。
    📌 这条曾经是「声称有、实际没有」：视角 2 第一句就写着「分类不同，规则集不同」，
    而三套规则集**一套都没给**。
18. **旋钮有四个且互相正交**（`craft-layer.md` 四之二）：**情绪基调**（Trust/Excitement/
    Professional/Creative）· **创作振幅 variance**（布局风险）· **信息密度**（装多少）·
    **精细度**（打磨到什么程度）。原来只有一个「语义四档」，把不同的事混在了一起。
    默认值：仪表盘/设置/表格 variance 4 · 落地页 7 · 作品集 8。
19. ⭐⭐⭐ **当代的默认坍缩比紫渐变高一层**（`craft-layer.md` 四之三）。
    黑名单里的紫渐变/三列网格已被广泛学会规避，于是坍缩到了三个「看起来有品味」的默认：
    **暖奶油+衬线+陶土** · **近黑+一个酸色** · **大报版式**。
    **二阶反射检查**：给这一版的美学命名一条赛道，然后问「光看品类能不能猜出这条赛道？」
    能猜出来就重做——**赛道该由这个品牌的具体之处挑出来，不是由品类挑出来**。
20. **签名赌注只下一个，且在建造那一步就建**（`craft-layer.md` 四之四）。
    ⛔ **不许推迟到「打磨」阶段**——推迟的签名 99% 不会发生。候选清单见该节。
21. **Delight ＝ 具体性，不是装饰**（`craft-layer.md` 第五章）。
    目标是**一两个用户会截图的瞬间**——不是彩带、不是弹跳、不是 emoji。
    四类候选按安全性排序（文案具体性 → hover 编排 → 状态转场 → 一个签名细节），
    **按动效强度门控**（≤3 只做文案；8+ 才做签名细节），且**必须交出「选择不做的候选及理由」**。
    ⭐ **可证伪判据（similar-prompt 自测）**：**把这一页的品牌换成同品类的另一个，它还能照样用吗？
    能 → 签名不够强。** 在交付前加强它，不要等评审时被问。
    ⚠️ 构图层也有 slop 且更隐蔽：某工具盲跑 10 次**全部**产出「左文右图」首屏，
    而 18 个真实参考页只有 3 个用它——**它什么都适合，是因为它什么都没承诺**。
22. **主观判断必须可辩护（taste is debuggable）**：
    「这感觉不对」**必须能追溯到一条被打破的原则**（本 skill 的某条规则、`visual-spec.md` 的节号、
    或 12 条认知模式之一）。追不到 → 降级为「待验证的直觉」，不进结构性发现。
    ⚠️ 反过来也成立：**规则挡不住的难看，仍然是难看**——规则让判断可复核，不是让判断变成打勾。
23. **交互质量分三层，只做门禁那层等于没做**：门禁（机械反模式，条数以 `--list-rules` 实测为准）· 走查（键盘走一遍 / 多选走一遍 /
    撤销走一遍）· 评审视角（UE 的 Trunk Test / Goodwill / Mindless-choice）。
    **状态模型的唯一权威源是 `references/interaction-patterns.md`**（四类 · 三段式）。
    ⛔ **任何其他文件不许复述状态数量**——此前五处各写各的（10 态 / 6+3 / 7+3 / 8 态），
    **同一个按钮按不同入口执行会得到不同结论**。
    判据：**列出属于哪几类 → 每类哪些适用 → 不适用写一句为什么**。
    ⚠️ **凑齐比缺失更糟**：制造出来的状态会被当成真需求实现。
    唯一无条件必须的是 **focus**（无障碍硬门 A 层）。
    ⭐ **平台交互、无障碍、法规合规这三类有权威正本**（HIG / WCAG-ARIA / 法规原文），
    一律先找正本，**不许用通用语料的缺失反推「不存在」然后自己填空**（见 M6）。
24. **每条动效必须先过四问闸门**（频率 → 目的 → 速度 → 功能），且**目的必须是六个词之一**
    （反馈/空间一致性/状态指示/防止跳变/解释/愉悦）。**说不出就删掉。**
    键盘发起的动作与 100+次/天的元素**一票否决，永不动画**。
    每条动效还必须写明 **reduced-motion 降级后的样子**——降级不是可选项，**但降过头（把反馈全灭掉）也是缺陷**。
25. **安全不许只活在细则里。** SEC-1~10 每条必须有结论（不许空着），`sec-scan.py` 机械层无发现，
    **产品级安全规则必须有 PRD 附件 C 依据**——PRD 没写就登记 GAP 回 S4，不许自己替产品定权限模型。
    ⚠️ 通用工程基线（注入/XSS/限流/泄露）**不需要 PRD 授权，默认执行**，PRD 没写不构成豁免。
    📌 这条曾经不在铁律里、也不在一页纸 SOP 的研发门禁里 —— 安全只活在 `s9-quality-gates.md` 一个文件中，
    而 SOP 自称「操作规程本体，照着这张表就能跑」。照着那张表跑，安全一次都不会被提起。
26. **无障碍与安全同型，必须在需求层有采集位。** 全局 NFR 最小集是**六类**（唯一真源＝`techspec-readiness.md` T7）：
    性能 · 并发 · 存储 · 兼容 · **无障碍**。缺任一类完备度门禁报红。
    📌 为什么：S5/S6 有 focus-visible/对比度/reduced-motion 门禁，但需求层此前零采集位，
    于是到 S8 按「不许猜补」的铁律，无障碍用例会**整类缺失，而每一步都守了规矩**。
27. **两种「覆盖率」必须分开叫、分开报**：
    **行覆盖**（代码行，默认 ≥80%，`s9-quality-gates.md`）与**需求覆盖**（FR↔用例，`s8-testcases.md`）。
    此前两者同名并列打勾 —— **用行覆盖 80% 去交需求覆盖的差**，是这种同名最典型的用法，且看不出来。
28. **格式边界必须守（M9）。** 任何 md 外发到飞书/钉钉/Figma：
    **写入前 `record` → 写入 → 回读 → `check --readback`**，三步缺一不可。
    **本地未动而远端指纹变了 → 红，禁止覆写**，先合并再推。
    ⚠️ **判据是结构指纹一致，不是「有没有报错」** —— 写入返回 success 而内容缺一大块是常态。
    ⚠️ Figma 链接必须 **node-id + 图层名双锚**；demo 场景必须带 `data-scene` / `data-fr`。
    📌 这条守的是**唯一一类不可恢复的丢失**：把别人在远端做的修改静默删掉。
29. **调研：广度 > 下游，颗粒度 ≥ 下游，深度挑 3–5 个穿透**（`s2-research.md` 〇之二）。
    ⚠️ **只反推深度是不够的**——如果调研范围恰好等于下游要填的字段，它只能**填表**，
    **不能提供参考、也无从借鉴**：下游的字段是**已经想到的**，
    而**竞品的优势往往在我们还没想到的地方**。
    ⭐ **必须单独列「竞品有而我们没有的」一节**——只对着自己的清单去查，
    **查到的永远是自己已经想到的东西**。
    颗粒度仍由下游字段反推（要填附件 D 就得实测竞品的字段与校验）。
30. **调研三路并行，缺哪路写明原因**：a 检索/爬取 · b **GitHub 高质量开源实现** · c **Codex 外包取数**。
    ⭐ b 路最容易被忽略而最值钱——**开源实现能读到闭源竞品看不到的状态机、字段校验、边界处理**，
    那正是附件 D/E 需要而黑盒观察拿不到的颗粒度。
    ⚠️ 同一结论**至少两路一致**才写进报告；**三路都说同一件事 ≠ 三个信源**（可能都在引用同一篇评测）。
    ⛔ **检索词一律用泛化品类词**，不许出现内部代号或未公开方向（交给 Codex 的要求书同样适用）。
31. **调研报告要「分析」不是「罗列」**：功能/设计/交互三个维度各做一遍**三层综合**
    （L1 惯例＝table stakes · L2 新势 · **L3 第一性**），L3 有洞察的写成 **EUREKA 句式**。
    ⛔ **反谄媚**：禁止「各有优劣 / 见仁见智 / 有多种思路 / 可以考虑」——
    **每条对比都要表态，并写明什么证据会推翻这个判断**。
    ⭐ 挑战竞品做法的**最强版本**，不是稻草人：先假设它是对的，再问它对在哪。
32. **调研的深度由下游模板反推，不由「研究员觉得够了」决定**（`s2-research.md` 〇之二）。
    下游要填附件 D 的字段规格，S2 就得实测竞品表单的字段与校验；要填设计令牌，就得量它的色值字距。
    **只查「有没有这个功能」的调研，填不了下游任何一个字段**，而它看起来是做过的。
    ⚠️ **广度不许缩**（五条线、八家竞品是底线），**深度挑 3–5 个功能穿透**——
    全都深挖做不完，全都不深挖等于白做。
33. **需求侧竞品必须单独列**（`s2-research.md` 三）：真正的竞争由**用户的处境**定义，
    唯一的问题是**「你的产品明天消失，他们会改用什么？」**——
    答案常常不是另一个 App，而是微信收藏 + 系统相册 + 一个命名混乱的文件夹。
    **只做供给侧调研，会做出一个「比同行更好但没人换过来」的产品。**
33a. **竞品分层必须双轴并存**（`competitive-research.md`）：竞争关系轴＝直接/间接/替代/潜在进入者，
    样本角色轴＝品类头部/直接对手/越级参照/反面样本。前者回答“怎样争夺同一进展/预算”，
    后者回答“为什么值得研究”；拿一套替换另一套会同时漏掉替代方案和失败教训。
33b. **横向对比必须同口径，AI 必须比结果与失败。** 深挖对象用同一任务、输入、账号档、端和完成定义；
    记录步骤/耗时/回退/错误/恢复，不把不同页面截图拼成优劣。AI 适用时还要比能力角色、效果、
    使用门槛、数据/评测、延迟/降级、成本/合规；只列模型名或“有 AI”不算研究。
33c. **研究与 PRD/Figma/HTML 双向对账。** `downstream-coverage.md` 一面从下游承重问题反查
    `CLM/INS/OPP/COMP`，一面给每条 high/medium 洞察和机会登记去向；无消费者可 `WATCH`，
    但不许删除。**覆盖下游不等于服从下游**——替代、反证、潜在进入者、邻接机会仍要多出来。
33d. **竞品实测必须按产品形态选通道并留 `RUN-xx` 回执。** Web 用浏览器控制工具遍历；
    macOS 原生应用只在用户明确授权具体产品/版本/官方来源后下载，再用 Codex Computer Use 遍历。
    没实际操作到结果不许标 `[实测]`；下载/浏览授权不自动授权付费、发布、发送、删除、改真实账号或新增系统权限。
    “已遍历”只能指**当前可达范围**：发现的一级模块都有覆盖行，未覆盖/阻断都写原因，不能暗示隐藏档位也查过。
33e. **最终竞品名单必须能解释它怎样形成。** 先写待支持的决定、定位镜头与用户选择张力，
    再扩候选池、记录纳入/排除/重看触发，并按维度制定一手证据/独立复核/实测/降级计划。
    威胁价值与学习价值分列，⛔ 不合成总分；否则研究员能靠删样本或平均分制造想要的结论。
34. **S3 做的是产品定义，不是打磨 S1**（`s3-definition.md`）：
    **从 S1 的用户需求 + S2 的调研分析中得出**——只有其中一个就动笔即违规
    （只有 S1 是把用户的话抄一遍；只有 S2 是竞品综述）。
    ⚠️ **它是全流程最贵的一个决定**：WHAT 错了，要到六七个阶段之后才知道，
    那时设计、交互、代码全是沉没成本。
    ⭐ **「不做这个」是合法且高价值的结论**——证据不支持就出 `no-build.md`，**停在这里是成功**。
    ⭐ **至少生成 3 个互不相同的定义候选**（把产品名互换后读者看不出差别，那就是一个候选）；
    只给一个 = 从第一个想法倒推理由，而第一个想法通常是品类默认。
35. **定义必须覆盖下游 18 项**：下游每一处需要「产品层决定」的地方，定义里都要有答案。
    答不上来的，下游只能自己发挥——**而那部分不在任何需求文档里**。
    尤其：**不服务谁 · 明确不做 · 载体 · 是否 AI · 成本量级 · 护栏指标 · 数据边界 · 情绪基调**。
36. **单向门必须在 S3 点名并拍板**：按「可逆性 × 量级」分类，
    **单向门**（服务谁 / 载体 / 数据模型 / 埋点 schema / 品类定位 / 是否依赖模型）走过去回不来，要慢要充分；
    **其余默认是双向门**，70% 信息即可决定——**在双向门上追求完美是本阶段最常见的浪费**。
    ⚠️ 漏掉一个单向门的代价，在半年后才出现。
37. ⭐⭐ **S2–S7 是产品与设计主导的，技术方案是研发主导的**（`techspec-readiness.md` 〇之二）。
    S2–S7 的目的是**把需求、设计、交互说明确**；研发据此输出技术方案，然后才开发。
    **判据**：一件事如果**换一个技术栈答案就变**，它属于技术方案；
    **换技术栈答案不变**，它属于产品/设计，必须在 S2–S7 给出。
    ⛔ 产品**不定**：接口路径与协议 · 错误码命名 · offset 还是 cursor · 索引与存储选型 ·
    前后端各自怎么判权限 · 迁移脚本 · 部署环境。
    ✅ 产品**必须给它们的另一面**：有哪些错误场景与用户看到什么 · 数据量级与一屏多少 ·
    角色×操作矩阵与越权时用户看到什么 · 老数据能不能丢与回滚时用户视角发生什么 ·
    上线后要能回答哪些问题。
    📌 我在 2026-08-31 的联合评审里越过这条线一次——把「错误码表」「前后端各自怎么判权限」
    「迁移脚本」写进 PRD 要求产品填，**那是替研发做技术决定**。已收回。
38. **S2–S7 的验收判据是「能不能据此写出技术方案」**，不是「能不能开始写代码」——
    这是更早也更严的一道线（`techspec-readiness.md` T1–T14）。
    三个词各自有归属：**准确**（M2 三来源）· **明确**（`requirements-quality-gate`）·
    **细节 ok**（本表，此前没有任何东西验这一层）。
    ⚠️ 一条需求可以既准确又明确，却**细不到能让人做技术决策**——
    「单次上限 500 张」是准确且明确的，但它没说数据怎么存、并发怎么办、十万张时还成不成立。
39. ⭐⭐⭐ **门禁全绿证明不了这份物料是好的**（`substance-over-theater.md`）。
    机械判据判的是**「填了没有」**——章节在不在、ID 对不对、有没有数字。
    **一段结构完整、每道门禁都绿的内容，可以完全不驱动任何决定。它是家具。**
    ⚠️ BMAD 把术语漂移/ID 连续性这类检查明确归为**「尾注，不驱动结论」**——
    **而本 SOP 的 45 道门禁 + 5 个专项扫描，几乎全部住在那一节里。**
    ⛔ **不许拿「全部门禁全绿」回答「这份物料行不行」**，那是两个问题。
    ⭐ **互换测试**：把产品名换成同品类竞品，这段话还成立 → 它没有信息。
    （工艺层早有这条，只是一直只用在视觉上——**摆设通常文笔很好**，越顺越容易全绿。）
40. ⭐⭐ **过度形式化和形式化不足同样是缺陷**。
    本 SOP 的默认动作是把 25 节模板套到一切东西上——**这本身是个缺陷**。
    给单人内部工具写八条用户旅程是负担，消费级产品一条旅程没有是缺失，**两个方向都要报**。
41. **抽象的批评是怯懦**。评审必须给位置、引原句、点名缺什么——
    「这部分不够具体」本身就不够具体。
    ⭐ **严重度排的是对有用性的影响，不是修起来容易不容易**：
    一句空洞的愿景是 critical（改一段就好），术语大小写不一致是 low（哪怕四十处）。
42. ⭐⭐ **界面元素也需要 ID 链**（`element-identity-gate.py`）。
    M1 的 ID 链管的是**条目**（需求/机会/假设），**管不到界面元素**——
    于是规格里的按钮、HTML 里的 DOM、Figma 里的图层、用例里的选择器**四处各叫各的名字**。
    ⚠️ **对不上不会让任何东西报错**：改了一个按钮，Figma 里找不到它是哪个，
    用例里的选择器悄悄失效，全程静默。
    ⛔ **按功能命名，不按内容命名**：`welcome-message` 坏在文案会变，
    `blue-button` 坏在把令牌钉死进了名字里，`first-paragraph` 坏在位置不是用途。
43. **说不清就先别写规格**（逻辑解释测试）。
    「我能不能不含糊地说清这东西为什么存在、怎么工作？」——
    **逻辑上的空缺会原样变成代码里的 bug。**
    落点是元素标识表的**「服务哪条需求/驱动力」**一栏：
    填不出来的元素，要么是没想清楚，**要么它根本不该在这一页上**。
44. ⭐⭐⭐ **「评审收敛」不是「市场风险收敛」**（`evidence-levels.md`）。
    本 SOP 的收敛机制全部是**内部**的——多视角、换上下文、换模型、机械门禁。
    **它们提高文档与逻辑的质量，证明不了产品值得做。**
    ⛔ 单向门决定与 S3 拍板**最低 E2**（和真实目标用户谈过）；
    ⚠️ 写 E0 不违规，**写了 E0 却不写「补之前只允许做到哪一步」的停止线才违规**——
    那等于承认没证据然后照常往前走。
45. ⭐⭐ **裁剪必须开工前声明并留痕**（`flow-tailoring.md`）。
    **被裁掉的环节和「跑了但没发现问题」的环节，在产物上长得一模一样。**
    ⛔ 不许执行时静默跳过——事后无人能分辨它是被裁了还是被忘了。
    ⭐ 定档看五问，其中**「谁来接」权重最大**：ID 链、双向对账、格式边界、元素身份
    存在的唯一理由是**有人要接手，而他不在你脑子里**。
46. ⛔ **S9 默认是 Handoff 模式，不是 Build**（`s7-s9-build.md`）。
    「从产品方案做到上线代码」**不等于我已经拿到仓库、部署和上线的权限**。
    **阶段推进不等于权限扩大**——进 Build 要用户明确说「你直接在仓库里做」，
    而**授权写代码 ≠ 授权上线，那是两次授权**。
47. ⛔ **S10 只有实测值没有决定，不算跑过**（`s10-retro.md`）。
    四个决定：继续 / 扩大 / 调整 / 停止。
    ⚠️ **「再观察一段时间」不是第四个选项**，它是「继续」加一个新观察期，
    必须写明看到什么就转停止，否则是无限期缓刑。
    ⭐ **验证测量必须在验证效果之前**；⚠️ 样本不足写「读不出来」，
    ⛔ **不许写成「无明显变化」**——「没有变化」有三种来源。
48. ⭐⭐⭐ **停止线是拦截，不是提醒**（`evidence-levels.md` + `templates/state.md`）。
    E0/E1 的结论必须写「补之前只允许做到哪一步」，而那一行
    **登记在 `state.md`，并作为对应阶段的入场条件**。
    ⚠️ 此前停止线只写在 `definition-final.md` 里，**没有任何阶段读它**——
    ⭐ **记录了不等于执行了**：写完「E0 + 只做到 S6」照样一路走到 S8。
    解除只有两条路：补到要求的等级，或**用户明确拍板承担风险**（记下是谁、哪天）。
49. ⭐⭐ **设计规则分四层，不许都写成「无例外」**（`design-rulesets.md` 三之二）。
    A 无障碍与安全硬门（无例外）· B 产品类型默认值（可覆盖，写理由）·
    C 品牌与设计方向（项目自定，定了就锁）· D 评审启发式（不进门禁）。
    ⭐ **判据：问「金融终端 / 开发者工具 / 内部后台 违反它是不是合理的？」
    答「是」→ 它最多是 B 层。**
    ⚠️ 混层的后果不是啰嗦，是**把「与默认风格不同」误判成「设计质量不合格」**。
50. ⛔ **状态是「适用即必须」，不是「凑齐十个」**。
    页面业务态 7 种 · 组件交互态 3 种，**两层分开**；不适用的写一句为什么。
    唯一无条件必须的是 **focus**（A 层硬门）。
    ⚠️ **凑齐比缺失更糟——制造出来的状态会被当成真需求实现出来。**
51. **任何验证工具在被信任前必须先自证会出声**（M8）：正例绿 / 每类反例红 / 无效输入报错 / 人工核实每条命中。**没见过它变红，就等于没有这道门**；报出的问题也要核实，假阳性会让人对告警脱敏。工具改动或路径变化后必须重跑自证。
52. **数字一律实测锚定**：文档里的数量声称（脚本数/用例数/门禁数/条数）必须机器实测，
    且实测不早于对象最近改动；「某产物有多少缺陷」类计数必须带测量时间戳——
    不带时间戳的缺陷数会在别人修好之后继续指控人家。
    📌 2026-09-09 做映射表时发现：P9 有三道元规则在守（script-count /
    selftest-count-measured / rule-count），铁律全集里却没有基条——原则悬空，本条补上。
