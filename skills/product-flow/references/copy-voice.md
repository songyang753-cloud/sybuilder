# 文案：Voice 与 Tone（附件 F 原来只有字数上限）

> PRD 附件 F 原本只管**字数上限**与「需市场确认」。
> 而文案真正的失败不是字太长，是**读起来像十二个人写的**。
>
> 来源：`educlopez/ui-craft` 仓内的 UX Copy 参考文件（2026-08-31 精读）。

---

## 一、Voice 恒定，Tone 随语境变

- **Voice 是产品的人格**——无论读的是引导、报错还是付费墙，它听起来都是同一个人。
- **Tone 是这个人格对语境的调整**——引导时更暖，成功时更收，破坏性确认时更明确。

> **Voice 一致而 Tone 有反应 → 读起来是「设计过的」。
> Voice 漂移 → 读起来像十二个人写的。**

## 二、Voice 三轴矩阵（在附件 F 顶部锁定，全篇回查）

| 轴 | 两端 | 怎么锁 |
|---|---|---|
| **正式度** | 正式 ↔ 随意 | 定一个位置，**写一句样例句**，再各写一句两端的极值做对照 |
| **庄重度** | 庄重 ↔ 诙谐 | 庄重＝把用户的任务当正经事；诙谐＝允许机智、承认荒诞。**选一个** |
| **专业度** | 专家 ↔ 新手友好 | 专家＝默认懂术语；新手友好＝首次出现时解释。**不同受众的界面可以不同，但要写明** |

⛔ **「友好」不是一份 brief。**
✅ 「随意但尊重、新手友好、略带诙谐」才是——**写手能照着执行**。

## 三、Tone by Context（九种语境，各有各的调）

| 语境 | 调 | 例 |
|---|---|---|
| 引导 onboarding | 暖 + 具体 | 「先把第一个项目放进来，大概 60 秒。」 |
| 错误·用户可恢复 | 诚实 + 可行动 | 「草稿没保存成功。重试，或复制错误码给客服：`abc-123`。」 |
| 错误·系统故障 | 诚实 + 透明 | 「搜索暂时不可用，我们正在排查。**你的数据是安全的。**」 |
| 成功 | **收着** | 「已保存。」——不是「太棒了！」 |
| 破坏性确认 | 把后果说明白 | 「删除 3 项？回收站里可以恢复 30 天。」 |
| 空态 | 面向动作 | 「还没有集成。连接 Slack、GitHub 或 Linear 开始。」 |
| 付费墙 / 限额 | 告知，**不羞辱** | 「免费项目已用 5/5。升级可创建更多。」 |
| 危险区（设置） | 中性 + 精确 | 「删除工作区会移除全部 47 个项目，并使所有 API 密钥失效。」 |
| 等待 / 延迟 | 对时长诚实 | 「正在生成报告，通常 20–40 秒。」 |

⛔ **绝不**：错误提示用感叹号 · 企业语境用 emoji · 例行保存放庆祝文案。

## 四、可读性硬指标

- 句 **≤20 词**，段 **≤3 句**，一句话一个意思
- **具体名词优于抽象**（「发票」胜过「计费凭据」）
- **主动语态**（「你已登录」胜过「登录已完成」）
- ⭐ **前置关键词**：关键的词或事实放在句子、标题、通知的**开头**——
  读者与读屏用户是**从头几个词决定要不要继续读的**。段落用倒金字塔：结论 → 支撑 → 背景
- ⭐ **缩写是一种税**：能拼出来就拼出来；必须重复使用的缩写在首次出现时定义
  （「预计到达时间（ETA）」），此后保持一致

## 五、写进附件 F 的形态

附件 F 顶部加一节 **F.0 Voice 锁定**：

```
Voice：<正式度位置> · <庄重度位置> · <专业度位置>
样例句：<一句代表本 voice 的话>
两端对照：<更正式的写法> / <更随意的写法>
```

其后每条文案表增加一列 **「语境」**（取自第三节九种之一），
使得「这句话为什么是这个调」可被复核。

## 六、诚实边界

- Voice/Tone **不可自动验**。门禁能查字数上限，查不出「这句话的调对不对」。
  它进报告的形态是「已按三轴与九语境走查，发现 N 处」，**不是 ✅**。
- 品牌层文案仍**需市场确认**（附件 F 原有规则不变）；
  本文件管的是**功能层文案的一致性**。
