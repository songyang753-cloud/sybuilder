# 动效规格库（S5.2 用）

> 本文件回答四个问题，顺序不能反：**该不该动 → 动多久 → 怎么动 → 关掉动效时长什么样。**
> 绝大多数动效问题不是「做得不好」，是**根本不该做**。所以第一节是闸门，不是参考。
>
> 来源：`emilkowalski/skills`（sonner/vaul 作者，★33430）· `LottieFiles/motion-design-skill`（官方）·
> `vercel-labs/web-interface-guidelines`。**冲突裁决见文末。**

## 一、四问闸门 —— 每个候选动效必须按顺序全过

> 记录每一问的答案，**它要进报告**。过不了就删掉，不要「先做了再说」。

### 问 1 · 频率：用户一天会看到几次？

| 频率 | 裁决 |
|---|---|
| **100+ 次/天**（键盘快捷键、命令面板、核心导航） | **否决。永不动画。** |
| 几十次/天（hover 态、列表导航、常用开关） | 否决，或只允许**近乎察觉不到**的动效（快、轻） |
| 偶尔（弹窗、抽屉、Toast、设置） | 合格——标准动效 |
| 罕见/首次（引导、空态、成功、庆祝） | 合格——**「delight 预算」只在这一档** |

⚠️ **键盘发起的动作是一票否决，不是判断题**——它一天重复几百次，动画会让它显得慢、延迟、断连。
Raycast 的命令面板没有开合动画，那是正确设计。

### 问 2 · 目的：它为什么要动？答案必须是下面六个词之一

- **反馈** —— 确认界面听见了用户（按下缩放、长按填充）
- **空间一致性** —— 说明它从哪来、到哪去（Toast 从哪边进就从哪边出；面板从触发它的位置长出来）
- **状态指示** —— 让状态变化可读（按钮形变、手风琴展开）
- **防止跳变** —— 内容凭空出现/消失/瞬移时搭一座桥
- **解释** —— 演示功能怎么用（**仅限营销页与引导**）
- **愉悦** —— **只允许出现在「罕见/首次」这一档**

**「看着酷」不在名单上。说不出上面六个词中的一个，就否决。**
这是把「该不该动」从品味问题变成可判定问题的关键机制——**目的是封闭白名单**。

### 问 3 · 速度：能不能待在预算里？
如果这个效果只有做成「慢而炫」才成立，它就没过闸门。

### 问 4 · 功能：动效在这里是帮忙还是碍事？
**用户正在「读」或「操作」的数据不许为了风格而动。** 装饰性鼠标跟随效果在营销页可以，
在银行 App 的功能性图表上，不动比动好。

### ⭐ 闸门之外的三条结构性规则（2026-08-31 补，来源 `Ryan-yang125/motion-lexicon`）

1. **动效必须由事件发起**——按下、选择、路由变更、状态更新、直接操作。
   **没有事件的动效就是装饰**（这与「idle 浮动/呼吸/流光」的禁令是同一条的正面表述）。
2. **为状态变化预留空间**——标签、按钮、记录在状态切换前后**保持几何不变**。
   预留了空间，才不需要用动效去「搭桥」掩盖跳变。
   ⭐ 这是「防止跳变」这个目的的**更根本解法**：最好的防跳变动效是不需要动效。
3. ⭐⭐ **第二个用户动作必须能打断、反转或落定第一个**。
   一个不可打断的动效，会把「界面在响应我」变成「界面在忙自己的事」——
   而**可打断性恰恰是「跟手」的真正来源**，比缩短时长更有效。
   ⚠️ 本条此前完全缺失：动效规格只管了「多久、怎么动、关掉时什么样」，
   **没管「动到一半用户又点了怎么办」**。

### 闸门的两条配套硬规则
- **产出封顶**：整个 App 最多 5–7 条动效建议，单个视图更少。按杠杆排序，不按做起来好不好玩排序。
- ⭐ **必须交出「被否决清单」**：列出 2–5 处你考虑过但**故意不做**的地方，各写死于哪一问。
  例：`CommandMenu.tsx:12 命令面板开合 —— 否决：键盘发起、100+次/天，永不动画。`
  **这一节是「动效规格」和「动效愿望清单」的分界线。**

> 拿不准要不要留时，**最强的一步往往是删掉它**。

## 二、时长

### 2.1 按控件分档
| 元素 | 时长 |
|---|---|
| 按钮按下反馈 | 100–160ms |
| Tooltip、小浮层 | 125–200ms |
| 下拉、选择器 | 150–250ms |
| 弹窗、抽屉 | 200–500ms |
| 营销/解释性 | 可以更长 |

**总则：UI 动效待在 300ms 以内。** 180ms 的下拉比 400ms 的更跟手。
⚠️ 弹窗给到 500ms 与总则的张力，裁决是：**>300ms 不是禁止，是举证责任倒置**——
UI 元素上任何慢于 300ms 的动效，拿不出理由就是一条缺陷。

更细的一档（含环境动效）：Tooltip/微反馈 80–120 · 按钮/开关 120–180 · 图标转场 150–250 ·
卡片进出 200–350 · 弹窗 300–400 · 页面转场 400–600 · 戏剧性揭示 600–1200 · 环境动效 2000–20000ms。

### 2.2 距离 → 时长缩放（等距不等时）
`50px=0.8× | 100px=1.0× | 200px=1.3× | 300px=1.5× | 400px=1.6× | 整屏=1.8–2.0×`
**同一时长套在不同位移上，短距离显得拖沓、长距离显得仓促。**

### 2.3 进 / 出时长比
`出场 = 入场的 65–75%`。用户已经决定关掉它了，不要让它慢慢消失。

### 2.4 交互反馈延迟上限（这是「响应」不是「动效」，超了就是卡）
| 交互 | 上限 |
|---|---|
| Hover | <100ms |
| 按下 | <150ms |
| 松开/落位 | 200–300ms |
| 错误抖动 | 300–400ms |
| 长按 | 500–800ms |
| 拖拽启动 | **<50ms** |

### 2.5 材质 → 时长与过冲预算（把「质感」变成数值）
| 材质 | 时长系数 | 过冲 |
|---|---|---|
| 刚性（金属） | 1.2× | 0% |
| 弹性（橡胶） | 0.8× | 15–25% |
| 流体（水） | 1.5× | 5% |
| 纸（卡片） | 1.0× | 3–5% |
| 气体（烟） | 2.0× | 0% |
| 玻璃 | 0.9× | 0% |

过冲的场景预算：成功 5–10% · 错误 **0%** · 反馈 2–5% · 庆祝 15–25% · **高端感 0%**。

## 三、缓动

### 3.1 决策序
- 进场 / 出场 → **`ease-out`**（起步快，跟手）
- 屏内移动 / 形变 → **`ease-in-out`**
- Hover / 变色 → **`ease`**
- 匀速运动（跑马灯、进度） → **`linear`**
- 默认 → **`ease-out`**

### 3.2 ⛔ UI 上永不 `ease-in`
它起步慢，**恰好延迟了用户正在盯着的那一刻**。200ms 的 `ease-out` 感觉上比 200ms 的 `ease-in` 更快。
**这是 block 级规则，不是建议。**

### 3.3 内置缓动太弱，用强自定义曲线
```css
--ease-out:    cubic-bezier(0.23, 1, 0.32, 1);     /* UI 强 ease-out */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);    /* 屏内移动 */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);     /* iOS 式抽屉 */
```
行业标准曲线备选：MD3 Standard `(0.2,0,0,1)` · MD3 Emphasized `(0.05,0.7,0.1,1)` ·
Apple HIG `(0.25,0.1,0.25,1)` · Snappy `(0.2,0,0,1)` · Gentle float `(0.4,0,0.2,1)` ·
Bounce settle `(0.175,0.885,0.32,1.275)`。

### 3.4 弹簧
| 手感 | 刚度 | 阻尼 |
|---|---|---|
| 很硬 | 400+ | 25–30 |
| 标准 | 250–350 | 18–24 |
| 弹 | 150–250 | 10–15 |
| 很弹 | 100–200 | 5–10 |
| 柔和 | 100–150 | 20–25 |

阻尼 <1.0 会振荡，=1.0 是不振荡的最快解，>1.0 落位变慢。
推荐写法 `{ type:"spring", duration:0.5, bounce:0.2 }`；
**bounce 保持在 0.1–0.3，且大多数 UI 不该有 bounce**——留给拖拽消除和玩味交互。

## 三之五、可打断性：换个问法就查得了（2026-09-03）

「可打断？」这一列此前只能人填。⭐ **转折点是换问法**：
不查「它有没有被打断」（动态、难测），查「**它用的机制能不能被打断**」（静态、确定）——
CSS `transition` 从当前计算值重定向；`@keyframes` / `animation` 从 0 重启。
⇒ 瞬态或高频触发的元素（toast / tooltip / dropdown / menu / toggle / drawer / tab）
用 `animation` 就是不可打断，`interaction-gate` 第 17 条直接报。

⚠️ 只查得了**机制**，查不了**观感**（连点时看着顺不顺仍要人看）。
⚠️ 只看选择器名 —— 名字里不带 toast 的 toast 查不出来，**漏报不是误报**。

## 四、关掉动效时长什么样（`prefers-reduced-motion`）

> ⭐ **2026-09-03：这一节从「只能人工」变成可机器验。**
> `interaction-gate` 查的是**有没有写那个 `@media` 分支**；
> `browser-audit` 现在**真的模拟 `prefers-reduced-motion: reduce`**
> （CDP `Emulation.setEmulatedMedia`），逐屏量所有可见元素的
> `transition-duration` / `animation-duration`，>10ms 即红。
> ⛔ **有分支 ≠ 降级到位**：实测反例里分支只写了 `button`、漏掉 `.card`，
> 静态查分支的门对它完全无感，实测当场抓到 `div.card 240ms`。

> 这一节以前是整个体系的空白：所有 skill 都写「要尊重 reduced-motion」，
> **没有一个说降级后该长什么样**。

### 4.1 逐类降级对照
| 原动效 | 降级后 |
|---|---|
| 滑入 | **只留透明度淡入** |
| 弹跳 / 弹簧 | 瞬间完成，或简单 ease-out |
| 视差 | 静态定位 |
| 自动播放 | 暂停，改为用户发起 |
| 复杂编排 | 单次淡入 |
| 持续环境动效 | 静止，或极轻的透明度呼吸 |

**量化口径**：去掉空间位移 · 保留透明度 · 去掉弹簧缓动 · **时长砍 50% 以上** · 绝不自动循环。

### 4.2 ⚠️ 降过头也是缺陷
原则是 **gentler, not zero**。把所有反馈一并灭掉，用户会失去「界面听见我了」的确认。
保留透明度与颜色变化，去掉基于 transform 的位移。

### 4.3 前庭触发清单（必须提供替代）
大尺度缩放 · 全屏位置转场 · >100px 的旋转元素 · >2 层视差 · 快速换向。

### 4.4 认知无障碍
同一交互每次动效必须一致 · >5 秒的动效要有暂停控制 · **关键信息绝不能只靠动效传达**。

### 4.5 不止一个信号
除 `prefers-reduced-motion` 外，还要处理 `prefers-reduced-transparency`（毛玻璃降级为实色）
与 `prefers-contrast`（提高边框与文字对比）。

## 五、写进交互规格书的形态

每条动效在 `interaction-spec.md` 里必须写满**七列**，缺一即视为未定义：
⚠️ 本行此前写「六列」而下表实际是 7 列（2026-08-31 修）——**「可打断」那一列因此在模板里根本不存在**，于是「可打断性才是跟手的真正来源」这条判断没有落点。

| 触发（**必须是事件**） | 属性 | 时长 | 缓动 | **闸门四问的答案** | **可打断？** | **reduced-motion 降级后** |
|---|---|---|---|---|---|---|
| 点击折叠按钮 | `transform: translateX` | 200ms | `--ease-in-out` | 偶尔/空间一致性/在预算内/帮忙 | 是·反向 | 瞬间切换，无过渡 |

**没有第 5 列就不许进规格书**——它是闸门留痕，事后可查。
**没有第 6 列（可打断）就不算写完**——一个不可打断的动效会让界面显得在忙自己的事。
**没有第 7 列就不算写完**——降级不是可选项。

## 六、冲突裁决（两个来源打架时按这个走）

| 冲突点 | 裁决 | 理由 |
|---|---|---|
| 出场缓动：`ease-in` vs `永不 ease-in` | **UI 一律用 `ease-out` 或强自定义曲线** | 两者受众不同：一个面向动画播放，一个面向交互 UI。本流水线做的是 UI |
| 强 ease-out 常量：`(0.16,1,0.3,1)` vs `(0.23,1,0.32,1)` | **两者都可，但一个项目只准用一条**，写进 `DESIGN.md` | 混用会让同一产品里的动效手感不一致 |
| 「情绪→参数」有没有公式 | **有表可查，但表只产出默认值，不是判据** | 一方给了四原型×5 参数的映射表，另一方明确写「没有公式，调到对为止」。**用表当起点，用四问闸门与时长预算当门禁** |
| 起始缩放 | 不低于 `scale(0.9)` | 更低的起始缩放在 UI 上会读成「弹出」而不是「出现」 |

## 七、诚实边界

- 本文件管的是**该不该动、动多久、怎么动**。它管不了「这个动效好不好看」。
- 动效是否真的按规格实现，**读代码看不出来**——必须在真实渲染环境里看。
  静态截图看不见 Tweaks、动画与按钮切换，这类只能录屏或人工点。
- 断言动效时**用定性区间不用精确值**（可见 `opacity>0.8`、已淡出 `<0.1`）；
  **不要断言 transform**——`getComputedStyle` 返回的是 matrix。
- 自测量尺寸前必须注入 `*{transition:none!important;animation:none!important}`，
  否则量到的是动画中间态。
