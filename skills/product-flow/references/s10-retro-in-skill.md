# S10 · 上线后复盘 · 专节全文（从 SKILL.md 迁出；判据与 `s10-retro.md` 互补）

## S10 · 上线后复盘（流程终点不是上线）

**执行契约见 `references/s10-retro.md`，模板 `templates/retro.md`，门禁 `scripts/retro-gate.py`。**
⛔ **只有实测值、没有决定的 retro 不算跑过 S10**——四个决定：继续 / 扩大 / 调整 / 停止。


**为什么必须有这一阶段**：此前流程终点是 S8 上线，而
- 第五章定的**可量化目标**上线后没有任何机制去证伪
- 附件 B 登记的每条 `ASM-###`（**「我已经按它往下写了」的那些假设**）没人回头看它成不成立
- M7 只回流「本该被哪个视角抓到的**缺陷**」，**不回流「目标假设本身错了」**

**结果是这条流水线只会越来越擅长做文档，不会越来越擅长判断该做什么。**
逃逸缺陷是唯一的外部指标——而目标达成度是唯一的**方向**指标。

### 交付契约（`retro.md`）

| 项 | 判据 |
|---|---|
| **目标达成度** | 5.2 每个可量化目标：目标值 / 实测值 / 达成与否 / **数据来自哪个埋点与报表** |
| **埋点闭环** | 7.1 定的埋点**真的拿到数据了吗**？拿不到的逐条写原因（没埋 / 埋错 / 报表没建） |
| **假设结算** | 附件 B 每条 `ASM-###` 标 **成立 / 推翻 / 仍未知**；被推翻的写清「据此写下的哪些内容现在是错的」 |
| **明确不做的复审** | 3.2「明确不做」表里每条的**触发条件**，有没有被触发？ |
| **逃逸缺陷回流** | 线上问题逐条填 `lessons.md`，写清本该被哪个视角/哪道门禁抓到 |
| **护栏指标** | 摘要里定的护栏指标有没有被踩？踩了做了什么 |

⚠️ **「目标没达成」是合法结论，且比「达成了」更有价值** —— 它是唯一能改进 S3/S4 判断力的输入。
⚠️ **不许把没拿到数据写成「达成」**。拿不到数据的目标，结论是 `UNABLE`，
并且**这本身就是 7.1 埋点设计的缺陷**，要回流。

### M9 · 格式边界守卫（治「中间格式是 md，而终点不是」）

⚠️ **两条边界，不是一条**：
- **md → 远端**（飞书 / Figma / HTML）：见下文
- ⭐ **md → md**（阶段之间）：**大量中间产物靠 md 在阶段间传递**，
  三种衰减是 **丢项 · 改写漂移 · 静默降级**（后者最隐蔽：下游读起来完全通顺而约束已经没了）。
  守它的是 **`chain-gate.py` G0/G0.5/G0.8** + **ID 贯穿链（M1）**——
  **引用 ID 不会漂，复述文本会**。详见 `format-boundaries.md` 〇之二。

**本流水线的中间格式是 md，三个终点分别是飞书文档 / Figma / HTML。**
md「只有内容没有格式」会带来三类丢失，**危害顺序与显眼顺序恰好相反**：

| 类 | 表现 | 危害 |
|---|---|---|
| ① **写出去丢** | 4 列表格静默压成 2 列 · `write` 返回 success 而内容缺一大块 · 图片插错位置 | 高 —— **它看起来是成功的** |
| ② **读不回来** | **别人在飞书里改了，本地副本不知道，下一次覆写把它抹掉** | **最高 —— 不可恢复，且丢的是别人的工作** |
| ③ **表达不了** | 组件变体矩阵 / AutoLayout / 原型连线 / 焦点顺序 / 动效实际观感，md 里根本没有这个维度 | 中 —— 会被下游「自己发挥」补上，而那部分不在任何需求文档里，**就是 M4 的反向漏** |

⭐ **核心判断：md 不够富不是主要问题，md 没有身份才是。**
「表格不能合并单元格」只是难看；「远端被改了而我不知道」是**删掉别人的工作**。

#### 解法：不要把富格式塞进 md，塞进 sidecar

**md 保持可 diff —— 那是它作为中间格式的全部价值，不能为了排版牺牲。**
每份要外发的 md 配一个同名 sidecar：

```
prd/PRD-v2.md              ← 内容，可 diff，进 git
prd/PRD-v2.md.sync.json    ← 身份 + 本地结构指纹 + **上次回读到的远端指纹**，机器可读，进 git
```

于是三件事同时成立：**内容仍可 diff · 格式约束机器可读 · 远端漂移看得见**。

#### 三条硬纪律（每次外发必做，不许省）

1. **写入前登记**：`doc-sync-guard.py record <file.md> --url <链接> --kind feishu`
2. **写入后必须回读并比对**：`doc-sync-guard.py check <file.md> --readback <回读文件>`
   它逐张核**每张表的列数**、核标题集合、核图片数 —— **这三样正好是三种静默失败的指纹**。
   ⚠️ **判据不是「有没有报错」，是「结构指纹一不一致」。写入返回成功不等于内容进去了。**
3. **本地未动而远端指纹变了 = 红，禁止覆写。** 处置顺序固定：
   **先把远端改动读下来合并进本地，再推。** 工具不替你选一边。

#### 两条产物侧的契约

- **Figma 链接必须双锚**：`[F-01/pc/empty](链接#node-id=1-2)`。
  ⛔ **图层名用机器 slug（英文小写），不要用「空态」这类展示名**——
  ⭐ **展示名给人看，slug 给对账用；混用会让 G3 逐场景对账全部失配**（2026-08-31 修）。
  中文展示名想写就写在链接文字里：`[导入·空态](链接#node-id=1-2)` 另起一列。
  **node-id 在重排/重建后会失效，而链接看起来完好，点进去是别的东西**；图层名是语义锚，能重新解析。
  由 `doc-sync-guard.py figma-anchors <PRD.md>` 校验。
- **demo 场景必须带锚点**：`<section data-scene="f01-pc-empty" data-fr="FR-011,AC-1">`。
  ⛔ 命名是 **`fNN[-端]-<状态>`**（端可省，省略按 `*` 匹配任意端）；**状态用英文 slug**，与 Figma 图层名第三段逐字相同——G3 用这把三元键**正反两向**对账。
  无锚点的产物**无法对账**，`reconcile-gate.py` 会报「跑不了(2)」而不是「通过」。

#### 诚实边界

工具能守住**「有没有变」**，守不住**「变得对不对」**。
飞书里别人加的一句「这里要改」、Figma 里设计师调的 2px、HTML 里的实际手感 —— 只能靠人看。
`check` 不带 `--readback` 时**只校验了本地**，它会显式打印「未校验远端」——**那不是通过**。
