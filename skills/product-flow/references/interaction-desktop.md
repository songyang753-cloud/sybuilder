# 桌面交互四块（S5.2）

> 对文件类 / 相册类 / 列表类产品，这四块是交互的主干，而**通用设计语料几乎不覆盖**：
> 调研 16 个高分设计仓（12.4 万行）的结果是——多选的业务语义、右键菜单、重做与历史栈、
> 快捷键冲突仲裁，全部零覆盖或仅一句话提及。
>
> ⚠️ **但「设计语料没有」不等于「没有权威来源」。**
> 桌面平台的这四块，**平台人机界面指南（Apple HIG / Windows Guidelines）才是正本**，
> ARIA APG 是键盘层的正本。本文件标 📐 的条目取自平台指南，其余是按产品形态自定的。
> **凡与平台指南冲突，以平台指南为准。**
> ⚠️ 本文条目全部是**条件适用模式**：按产品任务与组件在场才适用（没有表格就没有表格模式，
> 没有多选就没有多选语义）——不是「所有桌面产品必须全上」的清单；不适用写一句为什么即可。

## 一、多选与批量操作

外部只给了键盘层（ARIA 的 `Shift+↑↓` / `Ctrl+A`）。**指针层与业务层全空。**

### 1.1 三种选择手势（缺一不可）

| 手势 | 行为 |
|---|---|
| 单击 | **替换**选择为该项 |
| ⌘/Ctrl + 单击 | **增减**该项，其余不变 |
| ⇧ + 单击 | 从**锚点**到该项的**区间**选择 |

⭐ **锚点规则**（做错了用户会觉得「选择乱跳」）：
锚点 = **最后一次非 ⇧ 的点击项**。连续 ⇧ 点击时**锚点不变**，区间从锚点重新计算——
而不是从上一次 ⇧ 点击的位置接着扩。

### 1.2 键盘层
方向键移动焦点（**不改变选择**）· `Space` 切换当前项 · `⇧+方向` 扩展选择 · `⌘A` 全选 ·
`Esc` 清空选择。焦点用 `aria-activedescendant` 或 roving tabindex，二选一，不混用。

### 1.3 ⭐「全选」的歧义必须显式消解

`⌘A` 到底选的是**当前视图里的 N 项**，还是**匹配条件的全部 M 项**？
这两者在有筛选或分页时完全不同，而多数产品在这里是沉默的。

**规范**：`⌘A` 只选当前视图已加载的 N 项。当 `N < M` 时，选中提示栏必须给出升级入口：

```
已选择 200 张（当前视图）          [ 选择全部 4,205 张 ]   [ 清除 ]
```

用户点了升级入口后，提示要变成明确的「已选择全部 4,205 张」，且**破坏性操作要二次确认**。

### 1.4 选中态的存亡（必须逐条回答，不许默认）

| 事件 | 选中态 |
|---|---|
| 滚动 | **保持** |
| 切换筛选 / 搜索词 | **清空**，并 Toast 告知「已清除选择」 |
| 切换视图（换导航项） | **清空** |
| 翻页 / 加载更多 | **保持**，且计数要包含未在视口内的已选项 |
| 某个已选项被删除 | 从选区移除，计数更新，**不报错** |

### 1.5 选中数 → 工具栏的映射

- **0 项：工具栏不出现**（而不是出现一排全灰的按钮——那是噪音，且违反「禁用不说明原因」）
- **1 项**：全部操作可用（含只适用单项的，如「重命名」「查看详情」）
- **N 项**：只适用单项的操作**隐藏**（不是禁用），其余可用
- 计数**始终可见**，且旁边永远有「清除选择」的出口

### 1.6 ⭐ 批量操作的部分失败

批量 10 项、成功 7 项失败 3 项，**是最常见也最常被做错的情况**。规范：

1. **不许只说「操作完成」**，也不许只说「操作失败」
2. 结果必须给出：`成功 7 · 失败 3`，且**失败项可逐条查看原因**
3. 提供**只重试失败项**的入口
4. **撤销只撤销成功的那 7 项**，且撤销本身也要能报告结果
5. 整批一次撤销，**不是逐项撤销**（见第三节）

## 二、右键菜单

外部语料只有 6 处一句话提及，**没有任何一处规定它与选中态的关系**——而那正是最容易做错的地方。

### 2.1 触发
右键 · `⌃`+单击（macOS）· 键盘 `ContextMenu` 键 · `⇧F10`。
**键盘触发时菜单出现在焦点元素旁**，不是鼠标位置。

### 2.2 ⭐ 与选中态的关系（三种情况，必须全部处理）

| 右键点在 | 行为 |
|---|---|
| **已选中的项上** | **保持当前选区**，菜单作用于**整个选区**（不要把选择缩成这一项） |
| **未选中的项上** | **先把选择替换为该项**，再打开菜单 |
| **空白处** | **清空选择**，显示容器级菜单（如「粘贴」「全选」「视图选项」） |

⚠️ 第二条是分水岭：**菜单绝不能作用于用户看不见的旧选区**。

### 2.3 菜单项排序
主操作 → 次操作 →〔分隔线〕→ **破坏性操作永远在最后**，且与其余项之间必须有分隔线。

### 2.4 多选态下的项
不适用于多选的项（如「重命名」）**隐藏，不要禁用**。
若必须保留，则禁用 + 说明原因（「重命名一次只能改一项」）。
**绝不允许沉默地只作用于选区里的第一项**——这是数据损坏级的错误。

### 2.5 键位
`↑↓` 移动 · `→←` 开关子菜单 · `Enter`/`Space` 激活 · `Esc` 关闭并**把焦点还给触发处** · 首字母跳转。

### 2.5b 📐 修饰键行为必须跨输入方式一致
`Option + 拖拽 = 复制` · `Shift + 拖拽调整尺寸 = 锁定比例`——
这些在触控板、鼠标、触摸下**行为必须相同**，不许在某种输入方式下失效。

### 2.5c 📐 hover 揭示自动隐藏的控件（本产品 RISK-2 的平台先例）
指针悬停时让自动最小化的控件重新出现，是平台自带的模式（如浏览器的最小化工具栏）。
这正是「界面两个音量」的平台先例——**不是自创交互，是在用平台已有的心智模型**。

### 2.6 铁律
**右键菜单里的每一项，都必须在别处也有入口。** 右键不能是任何功能的唯一通道——
触屏、辅助技术、以及不知道可以右键的用户会完全够不到。

## 三、撤销 / 重做 / 历史栈

外部一致背书「撤销优于确认」并给了 5–10s 的时长，但 **`redo` 与 `history stack` 全语料零命中**。

### 3.1 两档模型（必须明确每个操作走哪档）

| 档 | 载体 | 适用 | 时限 |
|---|---|---|---|
| **轻量撤销** | Toast 里的「撤销」按钮 | 可逆、效果肉眼可见（删除、归档、移动） | 5–10s；**用户可能还想用时不许自动消失** |
| **历史栈** | `⌘Z` / `⇧⌘Z` | 会累积的编辑（调色、裁剪、规则编辑、批量标记） | 会话内 |

⚠️ **两档不是二选一**：删除既可以有 Toast 撤销，也可以进历史栈。但**必须写明它走哪档**，
不写就会出现「Toast 过期后 ⌘Z 撤销了别的东西」这种最坏情况。

### 3.2 什么进栈、什么不进栈

| 进栈 | 不进栈 |
|---|---|
| 内容编辑（调整、裁剪、标记） | **选择变化** |
| 破坏性操作（删除、清理） | 视图切换 / 滚动 / 筛选 |
| 组织操作（移动、归类、重命名） | 纯展示偏好（密度、排序） |

⭐ **选择变化绝不进栈**——否则用户按 ⌘Z 期望撤销删除，结果只是恢复了上一次选择，
连按几次才撤到真正想撤的那步。这是最伤人的一种。

### 3.3 栈的规范

- 📐 **不要设不必要的撤销上限。** 人们期望**能一路撤回到打开文档、或上次保存时的状态**。
  只有在实现上确实撑不住时才设限，且要给出理由。
  ⚠️ 我最初把这条写成了「给一个具体数字如 50 步」——**方向是反的**，已按平台指南更正。
- **重做栈的失效**：撤销后若发生**任何新操作**，重做栈立即清空
- 📐 **提供「恢复到上次保存」** 作为便利入口（比连按 N 次撤销更符合用户真实意图）
- **跨会话**：默认不持久化；若持久化，必须在 UI 上让用户知道
- 📐 **批量撤销**：把一组相关的连续小改动（如连续拖动滑块）合并成**一步**撤销。
  批量操作同理，整批算一步，不是 N 步

### 3.3b 📐 撤销必须「说得出」也「看得见」（我最初完全漏了这两条）

**说得出——预告结果**：菜单项不许只写「撤销」，要写**描述性标签**：
`撤销 重命名` / `重做 加粗` / `撤销 删除 12 张照片`。
理由：人们不会记得上一步到底做了什么，**撤销前必须让他知道会撤掉什么**。

**看得见——撤销后结果要可见**：如果被恢复的内容不在当前视口里，
**必须滚动过去让它出现**。
理由：看不到结果的人会认为「没生效」，然后**重复按撤销**——
这会连撤掉他并不想撤的操作。这是撤销功能最常见的实际伤害。

### 3.3c 📐 不要覆盖系统级撤销通道
macOS 的编辑菜单、`⌘Z`/`⇧⌘Z`，以及触控板/设备上的系统撤销手势，**一律不许重定义**。
📐 macOS 上撤销与重做**放在「编辑」菜单最顶部**——Mac 用户永远先去那里找。
只有当系统标准通道确实覆盖不到时，才另加专用按钮，且要用系统标准符号、放进工具栏。

### 3.4 不可撤销操作
必须**显式列出清单**。这些操作：
- 走确认，且是**输入被销毁对象的名字**级别的确认，不是点「确定」
- 确认框里必须写清**后果与数量**（「删除 12 张照片？此操作无法撤销。」）
- **绝不出现在批量操作里而不加区分**

### 3.5 撤销优于确认
可逆操作**不弹确认框**，直接做，然后给 Toast + 撤销。
低风险操作弹确认框是明确的反模式——它训练用户闭眼点「确定」，
真正危险的确认框到来时也会被闭眼点掉。

## 四、快捷键体系与冲突仲裁

外部语料**没有任何键位表、冲突规则、可发现性规范**。

### 4.1 三层键位空间

| 层 | 例 | 规则 |
|---|---|---|
| **系统级** | `⌘Q` `⌘W` `⌘Tab` `⌘空格` | **绝不覆盖，一律让路** |
| **应用级** | `⌘K` `⌘F` `⌘Z` `⌘,` | 全局生效，**在任何视图下含义不变** |
| **视图级** | `1-5` 评分 · `F` 收藏 · `Space` 预览 | 仅在该视图生效 |

### 4.2 仲裁规则（按优先级）
1. 与系统级冲突 → **应用让路**，另选键位。
   📐 **唯一例外**：该标准快捷键对应的动作在本应用里**根本不存在**时，可以重定义
   （例：一个不做文本编辑的应用，`⌘I` 的「斜体」无意义，可重定义为「显示简介」）。
   除此之外一律不许挪用——用户会困惑于「我熟的快捷键在这里不一样」。
2. 视图级 > 应用级（同一按键在该视图内被视图级接管），
   **但必须在该视图的帮助里写明这条覆盖**
3. **同一动作在不同视图下键位必须相同**——不许「收藏」在这里是 `F`、在那里是 `S`
4. 焦点在输入框时：**除 `Esc` 与提交键外，所有无修饰键的单键快捷键让位**

### 4.3 单键快捷键
只在**焦点不在文本输入**时生效。这条不做，用户打字打到一半会触发一堆操作。

### 4.4 可发现性（三处都要有，缺一条快捷键就等于不存在）
1. **菜单项右侧显示键位**
2. **⌘K 命令面板的每条结果显示键位**
3. **`?` 打开快捷键总览**，按上面三层分组

### 4.5 与动效的联动
**键盘发起的动作永不加动画**——它一天重复几百次，动画会让它显得慢且断连。
这与动效四问闸门的问 1 是同一条，在两处都要写，因为两边的人不一定读同一份文件。

## 五、焦点管理（外部有成熟规范，此处只做整合与选型）

### 5.1 roving tabindex 四步
1. 容器内**只有一个**元素 `tabindex="0"`，其余 `tabindex="-1"`
2. 方向键移动时，把 `0` 移到新元素上，旧的置 `-1`
3. 移动后调用 `.focus()`
4. `Home`/`End` 跳首尾

### 5.1b 📐 Grid 的完整键位（权威表，照抄不要自创）

| 键 | 行为 |
|---|---|
| `→` / `←` | 焦点左右移动一格；到行首/行尾**不再移动**（不折行、不循环） |
| `↑` / `↓` | 焦点上下移动一格；到列首/列尾**不再移动** |
| `PageDown` / `PageUp` | 上下移动作者指定的行数，通常滚动到让当前可见区的末行/首行成为新的首行/末行 |
| `Home` / `End` | 移动到**当前行**的首格 / 末格 |
| `⌃Home` / `⌃End` | 移动到**整个网格**的第一格 / 最后一格 |

⚠️ 两条容易漏的：
- 方向键在格间移动时，**它们不能同时被用来操作格内的控件**（如下拉框）——
  必须先用 `Enter` 进入格内编辑态，`Esc` 退出。
- 若网格会动态加载更多行，`⌃End` 这类跳到末尾的键**要明确定义**是跳到「已加载的末尾」
  还是触发加载——不定义就会出现「按了没反应」。

### 5.1c 📐 多选列表的完整键位

| 键 | 行为 |
|---|---|
| `↑` / `↓` | 移动焦点到上/下一项 |
| `Home` / `End` | 移动到首项 / 末项（强烈建议支持） |
| `⇧↑` / `⇧↓` | **移动焦点并切换该项的选中态**（扩展选择） |
| `⇧Space` | 从**最近一次选中的项**到当前焦点项，连续选中 |
| `⌃⇧Home` / `⌃⇧End` | 选中焦点项及其之上/之下的全部项 |
| 输入字符 | **首字母跳转**：跳到下一个以该字符开头的项（>7 项的列表强烈建议支持） |

📐 **焦点落点规则**（多选列表获得焦点时）：
- 之前**没有**选中项 → 焦点落在**第一项**
- 之前**有**选中项 → 焦点落在**列表中第一个被选中的项**上（不是第一项）

📐 **两种多选交互模型，选一种并写明**：
① **推荐模型：不需要修饰键**——方向键移动焦点，`Space` 切换选中
② 需要修饰键的模型——`⇧`/`⌃` 组合
⚠️ 模型 ① 对只有键盘的用户友好得多。选 ② 时必须在帮助里写清楚。

### 5.2 三种容器模式（按产品形态选一种，不许混用）

| 模式 | 用于 | 键位 |
|---|---|---|
| **Grid** | 照片网格、卡片墙 | 四向方向键 · `Home`/`End` 行首尾 · `⌘Home`/`⌘End` 全首尾 |
| **Toolbar** | 顶部工具栏 | `←→` 移动，**整个工具栏在 Tab 序里只占一站** |
| **Feed** | 无限流 | `PageUp`/`PageDown` 跨条目，条目内用 Tab |

### 5.3 焦点指示器（两种形态，按容器选，别只会一种）
📐 **焦点环（halo）**：用于文本框、搜索框、单元格内的图像
📐 **高亮整行**：用于列表与集合（聚焦时用强调色底 + 反白文字；失焦时退回中性底）

规格：2px 描边 + 2px 外偏移，**对比度 ≥3:1**。
`outline: none` 必须有 `:focus-visible` 替代，否则是硬缺陷。

### 5.3b 📐 焦点不许无缘无故地动
**不许在没有用户交互的情况下改变焦点**——用户会被迫去找焦点跑到哪了。

唯一例外，且必须按下面分岔处理：**当前聚焦的元素消失时**
- 用户正在用方向键/键盘导航 → **把焦点移到最近的剩余元素**
- 用户不是在这样导航 → **直接隐藏焦点指示器**，不要瞎跳

### 5.3c ⚖️ 焦点与选中的关系（一处需要裁决的张力）
平台指南说「多数情况下聚焦一个项也就选中了它，除非自动选中会造成打扰的上下文切换」；
而多选列表的 ARIA 规范说「方向键移动焦点，`Space` 才切换选中」。**两者不矛盾，是分场景**：

| 场景 | 规则 |
|---|---|
| **单选**列表 / 侧栏导航 | 焦点即选中，方向键直接切换当前项 |
| **多选**列表 / 网格（相册、文件） | **方向键只移动焦点，不改变选中**；`Space` 切换、`⇧+方向` 扩展 |
| 焦点会触发重上下文的场景（打开新视图、加载详情） | **焦点不许自动选中**，必须显式 `Enter` |

判据：**如果自动选中会毁掉用户已有的多选，或会触发一次昂贵/打扰的上下文切换，就不许自动选中。**

### 5.4 焦点陷阱与返还
模态内焦点**必须被困住**（Tab 到底回到首个）；
关闭时**焦点必须还给触发它的那个元素**——不是还给 body。
用原生 `<dialog>` + `inert` 是最省事且最不容易做错的做法。
