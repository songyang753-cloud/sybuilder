# 跨产物对账门（M4 执行细则）

**这是本流水线最有价值的一道机制。** 每个阶段自己做得对没用——PRD 说的和 demo 做的不一样、demo 和 Figma 不一样、Figma 和代码不一样，才是真正的成本所在。

## 怎么跑（G1/G2/G3 已有工具，2026-08-30 补）

```bash
python3 scripts/reconcile-gate.py G1 prd/PRD.md                          # 功能 → 交互/验收
# 可运行原型：锚点运行时才写，先让矩阵门真走一遍把实测锚点导出来
node scripts/scenario-matrix-gate.mjs demo/demo.html --states demo/spec/states.json --dump demo/anchors.json
python3 scripts/gate-run.py scripts/reconcile-gate.py G2 prd/PRD.md demo/anchors.json   # 验收标准 → demo（⛔ 必须经 gate-run 分键落盘，裸跑=NOT-RUN）
python3 scripts/gate-run.py scripts/reconcile-gate.py G2 prd/PRD.md demo/demo.html      # 场景稿式旧 demo（静态 data-scene）
python3 scripts/gate-run.py scripts/reconcile-gate.py G3 demo/demo.html figma-link.md   # demo → 设计稿
python3 scripts/coverage_check.py handoff/testcases/requirements.md handoff/testcases/cases --gaps handoff/testcases/readiness.md  # G4 需求 → 用例（路径正本=s8-testcases.md ⑤ 的目录树；2026-09-15 对齐——旧写法少一级 testcases/ 且缺 --gaps）
# 退出码 0=双向通过 1=有漏 2=跑不了（无锚点/缺输入，**绝不折叠成 0**）
# ⚠️ G4 的 coverage_check 是**四态**：另有 3=对账通过但不能声称被测充分（有缺口/有 SKIPPED/没给 --gaps）——3 不是通过
```

📌 **此前四道门里只有 G4 有工具**，G1/G2/G3 全靠人工逐条核——
而 G2/G3 恰恰是 SKILL.md 自己列的「最容易出事的三个交接口」里的两个。
本文件下面那节还写着「对账工具自己也要先自证」，**而那三道门根本没有工具可自证**。

⚠️ **锚点契约是硬约束**（产物必须照此产出，否则门禁报「跑不了(2)」而不是「通过」）：
| 产物 | 锚点 |
|---|---|
| PRD 第四章 | `### M: <模块> / F-xx: <名>` |
| PRD 附件 A | `## FR-### 所属 F-xx` |
| demo | `<section data-scene="f01-pc-empty" data-fr="FR-011,AC-1">`；不演示的写 `<!--不演示 FR-012 理由:…-->` |
| Figma 回灌 | `F-01 \| pc \| empty \| <链接#node-id>`　⛔ **状态段用英文 slug，不用「空态」** |

⚠️ **无锚点 ≠ 通过。** 没有锚点的产物无法对账，门禁必须报 2 —— 这是三态契约的直接应用。

## 什么时候跑

**每次阶段交接必跑**，只读不改，产出 `reconcile/<交接>.md`。不通过 → 回上一阶段补，**不允许带病进入下一阶段**。带病进入的代价，在后面每一步都要重付一次。

## 唯一判据：双向覆盖

| 方向 | 问题 | 症状 | 严重度 |
|---|---|---|---|
| **正向漏** | 上游有、下游没有 | 需求没落地、功能没人设计、需求没测 | 高 |
| **反向漏** | 下游有、上游没有 | 无需求发挥：有人自己加了东西 | **更高** |

⚠️ **反向漏比正向漏危险**。正向漏是"少做了"，看得见、会被投诉；反向漏是"多做了没人要的"，它不在任何需求文档里，因此**永远不会被测试覆盖，也永远没人为它的缺陷负责**。绝大多数对账只查正向，这正是它们抓不到问题的原因。

## 四道门的具体判据

### G1 · S4→S5（功能 → 交互）

- 正向：每个 `F-xx` 有交互说明？
- 反向：交互稿里的每个界面能归到某个 `F-xx`？
- 附加：每个 `F-xx` 有异常场景？涉及输入的有字段级规格？（缺了 S8 生成不出用例）

### G2 · S5→S6（验收标准 → demo）

- 正向：附件 A 每个 `FR/AC` 有 demo 场景，或显式标注「不演示·理由」？
- 反向：demo 每个场景能反查到 `FR/AC`？
- 附加：`FR` 与正文第四章双向 ID 绑定完好？

### G3 · S6→S7（demo → 设计稿）

- 正向：demo 每个场景有 Figma 画面？**含非 happy path 状态**？
- 反向：Figma 里的画面都能对上某个场景？
- 附加：图层命名带 `F-xx`？（不带则 G4 无法对账）

### G4 · S7→S8（需求 → 实现与测试）

- 正向：每个 `FR` 有测试用例？
- 反向：每个测试用例能反查到 `FR`？
- 附加：每个 commit 能追到 `FR`？

## 报告格式

```markdown
# 对账 G2 · S5→S6　日期：2026-08-16

## 结论：不通过（正向漏 2 · 反向漏 1）

| 方向 | ID | 详情 | 处置 |
|---|---|---|---|
| 正向漏 | FR-031 | 锁定态无 demo 场景，也未标注不演示 | 回 S6 补场景 |
| 正向漏 | AC-2 | 计数器 15 分钟重置无从演示 | 标注「不演示·纯后端计时」 |
| 反向漏 | — | demo 有"记住我"勾选框，PRD 无此需求 | 回 S4 判：要则立 F-xx，不要则删 |

## 覆盖统计（只算真核过的）
- 附件 A 条目 24；已核 24；有场景 21；标注不演示 1；缺失 2
- demo 场景 22；能反查 21；无来源 1
```

## 硬约束

- ⚠️ **必须逐条核，不许抽样**。「我扫了一遍看着都有」不是对账。条目数要报出来，分母是真核过的数量。
- ⚠️ **不许边对账边改**。发现问题记下来，回上一阶段改——边对边改会让你既是运动员又是裁判，改完自然"通过"。
- ⚠️ **「不演示 / 不实现 / 不测」都是合法结论，但必须写理由并留痕**。默默跳过和显式豁免是两回事：前者是漏，后者是决定。
- ⚠️ **对账结论要能被别人复核**：贴出 ID 清单，不要只给结论句。

## ⚠️ 对账工具自己也要先自证（M8）

**用脚本做对账之前，先证明这个脚本会出声。** 对账工具坏了不会报错，它会安静地宣布「全部通过」。

开跑前四步（详见 SKILL.md · M8）：
1. 正例 → 绿；2. **每类漏各造一个反例（正向漏 / 反向漏 / 格式违规）→ 红**；3. 无效输入 → 报错退出而非绿；4. **人工核实它报出的每一条**。

📌 两条真实教训：
- **结论掩盖**：覆盖对账给出「覆盖率 100% + 双向全覆盖 + passed」，而那份 PRD 有 8 个缺口、整整一个功能零用例——数字全真，结论全错。
- **假阳性 ①（路径截断）**：用 grep 匹配形如 `references/<某文件>.md` 的引用时，把**另一个目录下的完整路径**截断成本地路径，误报文件缺失。
- **假阳性 ②（文档里的示意路径被当真）**：本文写下上面那条教训时，句子里的示意路径立刻被对账工具当成真实引用，又误报了一次缺失。**说明文档与被检对象混在同一棵树里时，扫描器分不清「引用」和「举例」**。
  → 规避：示意路径写成 `<某文件>.md` 这类不可能存在的占位；**但更根本的是执行 M8 第 4 步——人工核实它报出的每一条**。
  ⚠️ 假阳性不修的后果不是「多看两眼」，而是**所有人开始无视这个工具的告警**，从此它报真问题也没人信。

## 常见失败形态

| 形态 | 表现 | 为什么危险 |
|---|---|---|
| 只查正向 | 报告全是"XX 已覆盖" | 漏掉全部无需求发挥 |
| 抽样对账 | "抽查 5 条都对" | 缺陷恰好在没抽到的那批 |
| 边对边改 | 报告直接是"通过" | 没有不通过的对账门等于没有门 |
| 拿旧证据 | 复用上一轮的对账报告 | 上一轮之后产物已经改过 |
| 把 skip 当 pass | 覆盖率 100% 但含未核项 | 比没有报告更危险 |
