# S10 · 上线后复盘：把流程从「交付闭环」升成「学习闭环」

> 2026-08-31 第十一轮补入。此前复盘阶段只有 5 行、零 reference、零模板、零门禁——
> **它是九个阶段里唯一没有执行契约的那个**，于是最容易退化成一张数据报表。

## 〇、S10 要回答的不是「做得怎么样」，是四个决定

⛔ **一份只有实测值、没有决定的 retro 不算跑过 S10。**

| 决定 | 什么时候选它 |
|---|---|
| **继续** | 目标达成或在轨；假设没被推翻 |
| **扩大** | 达成且**归因清楚**（知道是哪一步起的作用，不是「整体上去了」） |
| **调整** | 目标没达成，但**问题定位得到**，且改动在双向门内 |
| **停止** | 关键假设被推翻，或投入产出不成立 |

⚠️ **「再观察一段时间」不是第四个选项**——它是「继续」加一个新的观察期，
必须写明**观察什么、多久、看到什么就转成停止**。否则它是无限期缓刑。

## 一、观察周期怎么定（此前完全没说）

⛔ 不许写「上线一个月后」这种与产品无关的默认值。

| 产品形态 | 周期由什么决定 |
|---|---|
| 高频（每天用） | **≥ 2 个自然使用周期**，且覆盖一个完整的周末 |
| 低频（每月用） | **≥ 2 个使用周期**——月度产品就是两个月，不能缩 |
| 有明显季节性 | 必须**跨过一次已知的波峰或波谷**，否则读到的是季节不是效果 |
| 需要养成习惯 | 到**留存曲线拉平**为止，曲线没平就没有结论 |

**样本量的诚实底线**：
- 达到多少样本这个指标才算读得出来，**在 S4 写目标时就要写**（7.1 埋点表）。
- 没达到 → 结论只能是 **UNABLE（样本不足）**，⛔ **不许写成「无明显变化」**。
  ⭐⭐ **「没有变化」有三种来源：机制没生效 / 样本不够 / 判据取值出界。
  把后两种写成第一种，是最常见的一种自欺。**

## 二、必须逐条结算的四本账

1. **目标账**：5.2 每个目标 → 实测值 → 达成 / 未达成 / **读不出来**（三态，不是两态）
2. **假设账**：每条 `ASM-###` → **成立 / 推翻 / 仍未知**；
   ⭐ 被推翻的假设要写**它当初是几级证据**（E0 被推翻很正常，E4 被推翻说明测法有问题）
3. **逃逸账**：线上暴露的问题 → 本该被哪一道门禁/哪一轮评审拦住 → 回流 `lessons.md`
4. **决策质量账**（⭐ 此前没有）：回头看 **S3 那次拍板**——
   当时的定义哪几条被现实推翻了？**下次在 S3 该多问什么？**
   ⚠️ 这一本是唯一能改进上游的账，也是最容易被跳过的一本。

## 三、指标异常时做什么（此前没规定）

| 现象 | 先查什么 | ⛔ 不许直接下的结论 |
|---|---|---|
| 指标没动 | **埋点有没有真的上报**（先验证测量再验证效果） | 「功能没用」 |
| 指标暴涨 | 有没有重复上报 / 内部流量 / 灰度放量混入 | 「效果很好」 |
| 指标下跌 | 同期有没有别的变更（版本、活动、渠道） | 「是这个功能拖的」 |
| 只有一部分人变好 | **分群看**——平均值可能掩盖了两个反向的群 | 「整体提升 x%」 |

⭐ **验证测量必须在验证效果之前。** 顺序反了，会把埋点故障读成产品结论。

## 四、出口：回流到哪里

S10 的结论**必须落到两个具体位置**，否则等于没跑：
1. `lessons.md` —— 逃逸缺陷与门禁缺口（这条已有）
2. **下一轮的 S2 / S3 输入** —— 被推翻的假设要作为**已知事实**进下一轮，
   ⛔ 不许下一轮重新把它当假设再假设一遍。

⚠️ **诚实边界**：S10 判不出因果，只判相关与「有没有被验证」。
要因果得靠 A/B，而 A/B 的开关在 S4 的 7.1 就该预留好——
**没预留的产品，S10 只能给出相关性结论，这一点必须在 retro 里写明，不许含糊过去。**
