# 状态模型（**唯一权威源**）

> ⛔⛔ **本节是全仓唯一定义状态的地方。** 其他文件只许**引用**，
> 不许复述数量、不许自己再列一遍（2026-08-31 立，外部评审第五次揪出同一处）。
> ⚠️ 此前有**五处**各写各的：10 态 / 6+3+特有 / 7+3 / 8 态缺一即未完成 / 模板里 7+3 且把
> Disabled 归进业务态。**同一个按钮按不同入口执行会得到不同结论。**

## 四类状态（不是一张清单）

| 类 | 谁有 | 成员 | 什么时候写 |
|---|---|---|---|
| **① 数据/流程状态** | 页面、列表、数据区、异步流程 | `default` · `empty` · `loading` · `success` · `error` | PRD（附件 E 状态机） |
| **② 组件交互状态** | **可交互元素**（按钮、输入、链接…） | `hover` · `focus` · `active` | S5.2 |
| **③ 可用性/权限状态** | 任何可被禁用或受权限控制的东西 | `disabled`（不可用）· `no-permission`（无权限，**文案不同**） | PRD（谁能用）+ S5.2（长什么样） |
| **④ 组件特有状态** | 由组件自身语义决定 | 如：已选中 / 展开 / 排序方向 / 已读未读 / **`pressed`（切换按钮开着，≠ `active`）** / **`visited`（链接点过，仅内容型产品适用）** | S5.2 |

### ⭐ 拿两个真实设计系统对过之后补的两条（2026-09-03）

在 `alphagov/govuk-design-system` 与 `primer/design` 里数状态词，发现我原来的模型漏了两件事：

1. **`pressed` 不等于 `active`** —— 我原来把它们混为一谈。
   `active` 是**按下的那一瞬**（class ②，松手就没了）；
   `pressed` 是**切换按钮当前处于开的状态**（class ④，持续存在，对应 `aria-pressed`）。
   ⛔ 混在一起的后果：规格里写了「按下态」，研发做出来的是瞬时高亮，
   而产品要的是「这个筛选器现在是开着的」—— **两个都叫「按下」，做出来是两个东西**。

2. **`visited`** —— 链接被访问过（class ④，仅链接有）。
   govuk 里出现 7 次不是偶然：**导航密集、内容型的产品**（政府服务、文档站、
   搜索结果页）里，「我点过哪条了」是关键的寻路信号，去掉它用户会反复点同一条。
   ⚠️ 应用型 UI 通常不适用 —— 按「适用即必须」写「不适用·理由」即可。

📌 顺带一个可用的经验分布：同一份 govuk 语料里
**`error` 出现 259 次，而 `empty` 只有 14 次**。
⇒ 表单密集的产品里，**失败态的规格文字通常要比空态多一个数量级**。
写状态清单时如果发现 error 那一格和 empty 一样短，多半是没写透。

### ⭐ 三条容易搞错的
1. **`skeleton` 不是独立状态**，它是 `loading` 的**表现策略**之一
   （另两种：spinner、渐进式内容）。选哪种由「预期时长 + 布局是否已知」决定，见下文§二。
2. **`disabled` 不是业务状态**，它是**可用性状态**——
   业务上「没有数据」（empty）和「你不能用」（disabled）是两回事，视觉与文案都不同。
3. **`no-permission` 必须与 `disabled` 分开**：前者要说「谁能给你开权限」，后者只要说「差什么条件」。

## ⛔ 判据是「适用即必须」，不是「凑齐」

三段式，缺一段都不算写完：
**① 列出这个对象属于哪几类 → ② 每类里哪些成员适用 → ③ 不适用的写一句为什么。**

⚠️ 关闭按钮只有 ②③④；一个数据列表只有 ①；一个提交按钮四类都有。
⛔ **凑齐比缺失更糟——制造出来的状态会被当成真需求实现出来。**
✅ 唯一无条件必须的是 **`focus`**（无障碍硬门 A 层，见 `design-rulesets.md` 三之二）。

| # | 状态 | 阶段 | 定义 | 视觉要求 | 时序约束 |
|---|------|------|------|---------|---------|
| 1 | **Default** | PRD | 未交互的初始状态 | 清晰可见、可操作外观 | — |
| 2 | **Empty** | PRD | 无数据可展示 | 空态插图 + 引导文案 + 主 CTA | — |
| 3 | **Skeleton** | PRD | 内容加载占位 | 灰色块 + 微光动画，形状匹配真实内容 | ≤2s 后替换 |
| 4 | **Loading** | PRD | 异步操作进行中 | 禁用交互 + 进度指示 | 分段策略见§二 |
| 5 | **Success** | PRD | 操作成功 | 成功确认（样式按项目设计方向定，⛔ 不规定必须绿色） | 1-3s 后自动恢复或跳转 |
| 6 | **Error** | PRD | 操作失败/校验不通过 | 红色边框 + 错误文案，焦点移至首个错误 | — |
| 7 | **Disabled** | PRD | 条件未满足/无权限 | 降低对比度（≥3:1 仍可读），cursor:not-allowed | — |
| 8 | **Hover** | S5 | 鼠标悬停（仅桌面端） | 微妙变化（亮度 ±5% / 下划线 / 阴影） | 即时，0ms |
| 9 | **Focus** | S5 | 键盘焦点 / Tab 选中 | 高对比度焦点环（2px，非 shadow） | 即时 |
| 10 | **Active** | S5 | 按下/点击瞬间 | 明确反馈（缩放 / 颜色变深） | ≤100ms |

⚠️ 每个交互元素至少覆盖其中**适用的状态**，不适用的写「不适用·理由」。

## 二、响应时间决策矩阵

| 延迟 | 用户感知 | 反馈策略 | 示例 |
|------|---------|---------|------|
| **0-100ms** | 即时 | 仅状态变化（Active→Default） | 按钮按下、toggle 翻转、checkbox |
| **100ms-1s** | 轻微等待 | Skeleton（已知布局）或 Spinner（未知布局） | 页面切换、列表筛选 |
| **1s-10s** | 明显等待 | 确定性进度条（知道总量）或步骤指示（不知总量） | 文件上传、搜索 |
| **>10s** | 后台化 | 通知 + 允许离开，完成后回调 | 批量导出、AI 生成 |

**Skeleton vs Spinner**：知道内容布局 → Skeleton；不知道 → Spinner。

**乐观 UI**：适用于高成功率操作（>99%），立即显示成功，失败时回滚 + Toast。

## 三、9 种通用交互模式

### 3.1 表单

- **校验时机**：实时(onInput) → 格式；失焦(onBlur) → 业务规则；提交(onSubmit) → 全量
- **多步表单**：进度指示 + 步骤可回退 + 草稿自动保存（间隔 ≤30s）
- **成功态**：确认页（关键操作）或 Toast + 跳转（轻量操作）
- **重置**：区分「清空本字段」和「重置整个表单」，后者需确认

### 3.2 导航

- **顶栏**：全局导航，≤7 项
- **侧栏**：工具型产品，可折叠，宽度 200-280px / 折叠 48-56px
- **底栏**：移动端，≤5 项，含当前态高亮
- **面包屑**：≥3 层时显示，每级可点
- **返回**：iOS 左边缘右滑 = 返回；Android 系统 Back；Web 浏览器后退

### 3.3 搜索

- **即时搜索**：<200 条本地数据，debounce 300ms，高亮命中
- **提交搜索**：大数据量，Enter / 按钮触发
- **搜索状态机**：空 → 输入中(显示清除按钮) → 搜索中(Loading) → 有结果 → 无结果(引导修改关键词)
- **搜索历史**：≤10 条最近搜索，可清除

### 3.4 空状态（四种来源，文案不同）

| 来源 | 语气 | 示例文案 | CTA |
|------|------|---------|-----|
| 首次使用 | 积极引导 | 还没有记录，创建第一条 | 创建按钮 |
| 搜索无结果 | 帮助 | 没有找到，试试其他关键词 | 清空搜索 |
| 已全部清空 | 确认 | 全部完成 | — |
| 功能不可用 | 解释 | 此功能需要升级 | 升级按钮 |

### 3.5 弹窗

**何时用 / 不该用**：

| 场景 | 用弹窗？ | 替代方案 |
|------|---------|---------|
| 不可逆操作确认 | ✅ 是 | — |
| 复杂表单（≥5 字段） | ✅ 是 | — |
| 阻断性错误 | ✅ 是 | — |
| 简单信息展示 | ❌ 否 | 内联展开 |
| 简单确认 | ❌ 否 | Toast |
| 列表选择 | ❌ 否 | 下拉/抽屉 |

**焦点管理**：打开 → 焦点进弹窗首个可聚焦元素；关闭 → 焦点回触发元素。
**关闭方式**：点遮罩 / ESC / 关闭按钮（至少两种）。

### 3.6 拖拽

8 状态：`idle` → `grab`(cursor:grab) → `dragging`(半透明 + 占位指示) → `over-valid`(高亮目标区) → `over-invalid`(禁止图标) → `drop` → `reorder-animation`(200ms) → `settled`

**无障碍**：必须有键盘替代方案（Space 抓取，方向键移动，Enter 放置）。
**手柄**：拖拽手柄用 `grip` 图标，不能把整行当手柄（会吞掉文本选择）。

### 3.7 错误处理

**层级**：字段级(inline) > 表单级(顶部汇总) > 页面级(全屏) > 系统级(全局 Banner)

**错误文案公式**：「发生了什么」+「为什么」+「怎么解决」

| 类型 | 处理 | 示例 |
|------|------|------|
| 可恢复 | 提供操作按钮 | 「网络异常」+ [重试] |
| 不可恢复 | 替代方案或客服入口 | 「账号已冻结」+ [联系客服] |

### 3.8 引导流

- 渐进式(逐步解锁) > 教程式(全局引导) > 提示式(tooltip)
- **必须可跳过** + 可重新触发（设置里找得到）
- 反模式：强制看完 5 步才能用、遮罩不可点击关闭、引导步骤太多（≤5 步）

### 3.9 手势（移动端）

| 手势 | 标准映射 | 不可违反的系统手势 |
|------|---------|-------------------|
| 左滑 | 操作菜单 | — |
| 下拉 | 刷新 | — |
| 长按 | 多选 / 上下文菜单 | — |
| 双指捏合 | 缩放 | — |
| 左边缘右滑 | — | iOS 返回（不可覆盖） |
| 底部上滑 | — | Android Home（不可覆盖） |

## 四、AI 交互模式（仅 AI 功能参考）

### 4.1 流式输出

- 逐字 / 逐段渲染 + 末尾光标呼吸动画
- **停止按钮**位置固定，不随内容滚动
- 停止后内容保留，可复制 / 编辑
- 生成完成 → 停止按钮变「重新生成」
- **自动滚动**：跟随最新输出；用户手动上滑 → 停止跟随 + 底部显示「回到最新」按钮
- **超时策略**：>30s 提示「生成时间较长」+ 允许后台等待

### 4.2 反馈收集

- **最小形态**：👍👎 两个按钮（结果右下角）
- **进阶形态**：👎 后展开原因选项（不准确 / 不相关 / 有害 / 其他）
- **隐式反馈**：复制 = 正面信号；重新生成 = 负面信号
- 反馈后确认：「感谢反馈」Toast（≤2s），不阻断操作
- ⚠️ 反馈文案属品牌调性，标注「需市场确认」

### 4.3 多候选

- 卡片 / 标签页展示 N 个候选（N ≤ 4，多了选择困难）
- 每个候选独立操作（采纳 / 删除 / 编辑）
- 「再来一组」按钮 + 已消耗额度提示
- 全部不满意 → 提供「手动输入」入口

### 4.4 渐进式细化

- 初始结果 + 输入框「告诉我怎么修改」
- 修改历史可回溯（撤销到任意版本）
- 每轮修改可选显示 diff（新增绿色 / 删除红色）
- ≥3 轮未满意 → 建议「重新开始」

### 4.5 上下文管理

- 当前上下文长度指示（进度条 / 百分比 / 「已使用 70%」）
- 接近上限（>80%）→ 提示「上下文即将用尽，建议新建对话」
- 清空确认（不可逆操作，走弹窗确认）
- 支持「固定上下文」（系统提示词、角色设定不随对话滚动清除）

## 五、设计原则速查

### Norman 6 大原则

| 原则 | 一句话 | 违反症状 | 修复方向 |
|------|--------|---------|---------|
| **可见性** | 功能要能被看见 | 用户说「找不到在哪」 | 提升视觉层级、增加入口 |
| **反馈** | 每个操作都要有回应 | 用户说「点了没反应」 | 加状态变化、Toast、动画 |
| **约束** | 限制错误操作的可能性 | 用户能做到不该做的事 | 禁用非法选项、收窄输入范围 |
| **映射** | 控件与效果的对应关系自然 | 用户说「这个开关控制什么」 | 标签明确、位置就近 |
| **一致性** | 相同操作相同表现 | 同一图标不同页面含义不同 | 统一组件库、统一行为 |
| **容错** | 允许撤销、提供恢复 | 误操作后无法挽回 | 加撤销、加确认、软删除 |

### Tognazzini Top 5（从 19 条中提取最实用的）

| 原则 | 一句话 | 实操 |
|------|--------|------|
| **Fitts 定律** | 常用操作目标要大且近 | 命中区按输入方式取：**桌面指针 ≥24×24 · 触屏 ≥44×44**；主操作按钮最大 |
| **防错优于纠错** | 用约束代替错误提示 | 日期选择器 > 手输日期；下拉选择 > 自由文本 |
| **延迟感知** | 用户对等待的容忍有阈值 | 见§二响应时间矩阵 |
| **可探索性** | 允许用户安全地试错 | 撤销、沙箱、预览 |
| **自主权** | 用户能控制自己的体验 | 可关闭引导、可自定义布局、可调整设置 |
