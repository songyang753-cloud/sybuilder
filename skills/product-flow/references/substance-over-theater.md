# 实质 vs 摆设：内容「在场」不等于内容「有用」

> 来源：BMAD-METHOD `prd-coach/prd-validation-checklist.md`（七维度 rubric）+ AJTBD 的 RAT。
> 2026-08-31 第九轮补入。

## 〇、为什么必须单独有这一层

本 SOP 到目前为止的全部机械门禁，判的都是**「填了没有」**：
章节在不在、ID 对不对得上、数字有没有、表格有没有数据行。

**这些判据有一个共同盲区：一段写得很好、结构完整、每道门禁都绿的内容，
可以完全不驱动任何决定。** 它是家具。

⚠️⚠️ 更难受的一条，必须写下来：
**BMAD 把「术语漂移 / ID 连续性 / 交叉引用能不能解析」这类检查
明确归为「尾注（Mechanical notes），不驱动结论」。**
**而本 SOP 的 45 道门禁 + 5 个专项扫描，几乎全部住在那一节里。**
门禁全绿只证明这份 PRD **机械上是干净的**，
它**证明不了这份 PRD 是好的**——那需要判断，而判断不可自动化。

⛔ 所以：**不许拿「全部门禁全绿」回答「这份物料行不行」。** 那是两个问题。

## 一、四种摆设（挨个点名，不许含糊）

| 摆设 | 长什么样 | 判据 |
|---|---|---|
| **人设摆设** | 人物画像写了三段，**但 PRD 里没有任何一个决定是因为它才这么定的** | 逐个问：删掉这个画像，哪一行会变？答不出＝摆设。**超过四个画像本身就是信号** |
| **创新摆设** | 「差异化」一节写了，但写它是因为模板有这一栏，不是因为 S2 真挖到了什么 | 差异点能不能追到 S2 报告的某一条？追不到＝摆设 |
| **NFR 摆设** | 「系统应可扩展 / 安全 / 可靠」——**形容词，没有本产品特有的阈值** | 这条 NFR 换个产品还成立吗？成立＝摆设。⚠️ 六类 NFR **齐了**也可能六条全是摆设 |
| **愿景摆设** | 一句愿景，**换成同品类任何一个产品都不用改一个字** | 见下「互换测试」 |

### ⭐⭐ 互换测试（PRD 侧的 similar-prompt）

工艺层早就有这条，只是一直只用在视觉上：
> **把品牌换掉，这套设计还能用 → 签名不够强。**

**同一个机制搬到文字上**：
> **把产品名换成同品类的竞品，这段话还成立 → 它没有信息。**

对**愿景、差异化、人物画像、成功指标**四处逐段做一次。
⚠️ 这不是文笔问题——写得越顺越容易通过所有门禁，**摆设通常文笔很好**。

### 红旗：一切都被抹平到中性
> **每个选择都「兼顾」了各方 · 每条 NFR 都「重要」 · 每个用户都「重视」这个产品。**

S2 早有反谄媚条款（禁「各有优劣」），但它**只管调研报告**。
⛔ **PRD 同样禁**：写了取舍就要写**放弃了什么**，不许只写选了什么。

## 二、⭐⭐ 形态适配（Shape fit）：模板不是越全越好

**本 SOP 的默认动作是把 25 节模板套到一切东西上，这本身是个缺陷。**

| 产品形态 | 什么是承重的 | 什么是负担 |
|---|---|---|
| 消费级 / 多干系人 B2B / UX 吃重 | 用户旅程（每条要有具名主角） | —— |
| **内部工具、单一操作角色** | 能力清单形态 | **用户旅程密度＝纯负担**；成功指标应是运维指标不是用户指标 |
| 合规 / 监管更新 | **约束可追溯，不容商量** | 用户旅程可能完全无关 |
| 存量改造（brownfield） | 现有代码引用必须准确；**新旧旅程必须区分** | —— |
| 链条顶端（喂 UX→架构→用例） | 下游可用性权重最高 | —— |
| 独立不喂下游 | —— | 可追溯性可以轻 |

⛔ **两个方向都要报**：
**过度形式化**（给单人内部工具写八条用户旅程）与
**形式化不足**（消费级产品一条旅程都没有）**同样是缺陷**。
本 SOP 此前只会报后者。

## 三、评审怎么写才算数

### 四档判定（每个维度一档）
`strong` / `adequate` / `thin` / `broken`

- **只在能增加信息的地方写发现。** `strong` 的维度可以一条发现都没有。
- ⭐ **严重度排的是「对这份物料有用性的影响」，不是「修起来容易不容易」**。
  一句空洞的愿景是 **critical**，哪怕它只要改一段；
  术语大小写不一致是 **low**，哪怕它出现在四十处。
- ⛔ **抽象的批评是怯懦**（*abstract criticism is failure of nerve*）：
  必须给位置、引原句、点名缺什么。「这部分不够具体」本身就不够具体。

### 七个维度（判物料好不好，与门禁互补）
1. **可决策性** —— 决策者能不能据此拍板？取舍是被摊开了还是被抹平了？
2. **实质 vs 摆设** —— 见上。
3. **战略连贯** —— 有没有一个赌注（thesis）？功能优先级是从它推出来的，还是「哪个好做先做哪个」？
   ⚠️ **成功指标验证的是不是那个赌注**——赌的是使用质量却拿 DAU 交差，是典型的破绽。**有指标就要有反向指标。**
4. **完成度清晰** —— 每条功能需求至少一个可测的后果。
   ⛔「优雅处理」「合理的性能」「用户友好」——**逐个揪出来**。这一维**下游最吃重，判要狠**。
5. **范围诚实** —— 不做的事是明说的，还是留给读者自己推的？
   **开放项密度**要和赌注大小匹配：低风险文档里一堆开放项没问题，**已经准备开工的文档里一堆开放项是阻断**。
6. **下游可用** —— 术语表在不在？同一个名词在各处是不是同一个写法？ID 连不连续？
   每一节单独抽出来还看不看得懂（交叉引用走术语而不是「见上文」）？
7. **形态适配** —— 见上。

## 四、⭐⭐ RAT：假设要按「错了会怎样」排序，不是按有几条

来源：AJTBD `ajtbd-rat`。本 SOP 已有假设登记（`ASM-xx`），但**只登记不排序**——
于是「这个词用户能看懂」和「这个市场根本不存在」并排躺着，权重一样。

**S3 产品定义收口时，从假设表里挑出 Top-5 最危险的**，按五类风险归位：

| 风险类 | 问的是 |
|---|---|
| 市场需求 | 这个需求真的存在吗？ |
| 细分是否值得做 | 存在，但这批人够多够值钱吗？ |
| 愿不愿意付出代价 | 想要 ≠ 会为它改变行为 / 付费 / 迁移 |
| 单位经济 | 每多服务一个用户，是赚是赔 |
| 需求可规模化 | 前面都成立，但它长不长得大 |

**判据**：一条假设如果**错了整个产品就不成立**，它必须在 Top-5 里，
并且**必须写明「用什么最小的动作能证伪它」**。

⭐ **最小证伪动作的量级参考**（来自 `product-value-proposition`）：
写 3–5 个不同的承诺句 → 挑**最便宜的载体**（故事板 / 一张 Figma 图 / 一个落地页）
→ 5–8 个目标用户的定性访谈 **加至少一个定量信号**（假门、等待名单、投放测试）。
⚠️ **只有定性没有定量，拿到的是礼貌**——愿意说「挺好的」和愿意留下邮箱是两件事。
⛔ 实验必须有**对照**和**事先写死的成功阈值**；阈值事后定＝没有实验。
⛔ 写不出证伪动作的假设，等于没有登记——它只会在上线后自己爆。

## 五、什么时候跑

| 时机 | 跑什么 |
|---|---|
| S3 定义收口 | 互换测试（愿景/差异化）+ RAT Top-5 |
| **S4 PRD 出场前** | **七维度全跑**，写成四档 + 发现清单 |
| S5/S6/S7 交付前 | 互换测试（视觉签名 = 工艺层的 similar-prompt；文案 = 本篇） |
| 任何一次「门禁全绿」之后 | ⛔ **再问一遍：它是好的吗？** 门禁答不了这个问题 |
