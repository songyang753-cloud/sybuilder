# 用例工程五件套模板（S8 测试章 / `--only testcases` 单跑通用）

> 形态正本 = `references/s8-testcases.md` ⑤ 的目录树；本文件是那五种产出物的**填空模板**。
> 2026-09-15 补（WO-002 终审）：此前五种产出物零模板——同 skill 里 PRD/研发计划/图都有模板，
> 唯独用例工程没有，属「要求交付的 ≠ 给了模板的」。
> ⛔ 五份产出各自独立成文件，按 ⑤ 的路径落盘；本模板只是把五份的骨架收在一处。

---

## 1 · `readiness.md`（就绪度判定 + 缺口清单；⭐ GAP 编号的唯一登记处）

```markdown
# 就绪度判定　日期：YYYY-MM-DD　文档：<PRD 名称与版本>

## 结论：可生成 / 部分可生成（N 个功能中 M 个可生成）/ 不可生成
<⛔ 只许这三种；「基本可以，我按常规补一下」不存在>

| 功能 | R1 验收 | R2 字段 | R3 异常 | R4 状态 | R5 权限 | R6 边界 | R7 前后置 | R8 可测性 | R9 安全依据 | 结论 |
|---|---|---|---|---|---|---|---|---|---|---|
| F-01 <名> | ✅/❌/⚠️ | | | | | | | | | 可生成/不可生成 |

## 缺口清单（唯一登记入口——写用例中途新发现的缺口也回填这里并顺延编号）

| ID | 功能 | 缺什么 | 具体到什么程度才够 | owner |
|---|---|---|---|---|
| GAP-01 | F-xx | | | <谁来补> |

## 本次不生成的部分
<功能清单 + 等哪些 GAP 补齐；已生成部分的覆盖率不含它们>
```

判定细则与硬约束见 `references/testcases-readiness.md`（逐功能判、GAP 带 owner、
空缺口清单是可疑信号、最大 GAP 编号必须在表里找得到）。

---

## 2 · `requirements.md`（抽取出的需求项清单）

```markdown
# 需求项清单　来源：<PRD 名称与版本>　抽取日期：YYYY-MM-DD　适配器：A/B/C/D

| 需求 ID | 出处（章节/行） | 类型 | 是否可测 | 备注 |
|---|---|---|---|---|
| FR-011 | 附件A · F-01 | 功能 | 可测 | |
| FR-0xx | §x.x | 功能 | ⛔ 不可测（无判据） | 进 GAP-xx |
| FR-0yy [待补规格·不生成] | §x.x | 功能 | 规格不全 | 等 GAP-yy |
```

⚠️ 自建编号（形态 B/C/D）要注明「测试侧自建，PRD 无原生编号」；⛔ 不回头改 PRD。
⚠️ `[待补规格·不生成]` 标在需求行上——`coverage_check` 靠它把该需求剔出分母，
且有人给它写了用例会被判「猜补」（退出码 1）。

---

## 3 · `cases/<F-xx>.md`（用例，按功能分文件）

```markdown
### TC-011-1　所属 FR-011 · AC-1
**标题**：<一句话，一条用例只验一件事>
**前置**：<写不出说明 R7 缺>
**步骤**：1. …　2. …
**预期**：<必须能在 PRD 找到原句出处；⛔ 不写「正常」「成功」>
**依据**：附件A FR-011 AC-1（原文：<抄原句>）　**类型**：等价类/边界/状态/异常/权限/安全/pairwise　**优先级**：P0-P3

### TC-012-1　所属 FR-012 **SKIPPED**
**SKIPPED 理由**：<为什么没跑——标记必须加粗且在头行，理由行必须紧随；见 s8-testcases.md ④>
```

设计方法（七类必做，安全用例最易整类缺失）见 `references/testcases-design.md`。

---

## 4 · `coverage.json`（生成物，⛔ 不提供模板）

由 `python3 scripts/coverage_check.py requirements.md cases/ -o coverage.json --gaps readiness.md`
生成——手写它等于伪造对账结果。字段语义与四态退出码见 `scripts/coverage_check.py` 文件头。
⚠️ `coverage_means_sufficient=false` 时（有缺口/有 SKIPPED），任何呈现覆盖率的地方
必须同时给出就绪度结论与未解决缺口数。

---

## 5 · `gaps.md`（诚实缺口视图；⛔ 只引用 GAP 编号，不另发号）

```markdown
# 诚实缺口　日期：YYYY-MM-DD

| GAP 引用 | 现象（哪些没生成/假覆盖在哪） | 为什么 | 影响谁 |
|---|---|---|---|
| GAP-01（登记见 readiness.md） | F-01 输入类用例整组未生成 | 无字段规格 | 执行测试的人会以为 F-01 已覆盖 |

## ④.5 自检记录（这套用例能抓到东西吗）
<挑 3~5 条 P0 假想需求改坏，逐条写「哪条用例会因此失败」；
发现假覆盖 ⇒ 回填 readiness.md 缺口表拿 GAP 编号，再在上表引用>
```
