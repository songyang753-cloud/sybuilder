# 全局卷（看一次，全项目通用）

## 性能约束

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| 首屏渲染 | ≤ 2s | P90，Lighthouse |
| 交互响应 | ≤ 100ms | P90 |
| 动画帧率 | ≥ 55fps | DevTools Performance |
| Bundle 预算 | ≤ 200KB (gzip, 首屏) | 构建产物统计 |
| 低端设备策略 | prefers-reduced-motion → 关闭非必要动画 | 媒体查询 |

⚠️ 嵌入式浏览器 / 低端安卓机特别注意：backdrop-filter、复杂阴影、大量 DOM 节点。

## 状态管理策略

| 归属 | 适用场景 | 持久化 | 示例 |
|------|---------|--------|------|
| 组件局部 | 仅本组件关心的 UI 状态 | 否 | dropdown 展开/收起 |
| 页面级 | 当前页面的筛选/排序/选中 | URL query（刷新保留） | 列表筛选条件 |
| 全局 store | 跨页面共享的业务状态 | 视情况 | 用户信息、权限 |
| 持久化 | 跨会话需保留的偏好 | localStorage / 服务端 | 主题、语言、布局偏好 |

⚠️ 写交互规格时，每个状态标注归属层级。研发按此决定状态管理方案。

## 桌面交互四块（判据见 `references/interaction-desktop.md`）

> 这四块对文件类/相册类/列表类产品是交互主干。**留空即视为未定义**，
> 到研发阶段必然出现「这里该怎么办」的追问。

### 多选与批量
| 项 | 本项目的定义 |
|---|---|
| 单击 / ⌘Click / ⇧Click | 替换 / 增减 / 区间（锚点＝最后一次非 ⇧ 的点击项） |
| **`⌘A` 选的是当前视图还是全部匹配** | <必答。N<M 时要给「选择全部 M 项」的升级入口> |
| 选中态在「换筛选 / 换视图 / 翻页 / 项被删」时 | <逐条回答，不许默认> |
| 选中数 → 工具栏映射 | 0 项**工具栏不出现**；1 项全可用；N 项隐藏只适用单项的 |
| **批量部分失败怎么回报** | <必答。成功 M 失败 N + 失败可逐条查 + 只重试失败项 + 撤销只撤成功的> |

### 右键菜单
| 右键点在 | 行为 |
|---|---|
| 已选中的项上 | 保持选区，菜单作用于**整个选区** |
| 未选中的项上 | **先把选择替换为该项**，再打开菜单 |
| 空白处 | 清空选择，显示容器级菜单 |

菜单项排序：主 → 次 →〔分隔〕→ **破坏性永远在最后**。
多选态下不适用的项**隐藏不禁用**；⛔ **绝不允许沉默地只作用于第一项**。
⛔ **每一项都必须在别处也有入口**——右键不能是任何功能的唯一通道。

### 撤销 / 重做
| 项 | 本项目的定义 |
|---|---|
| 哪些走 **轻量撤销**（Toast + 撤销，5–10s） | <> |
| 哪些走 **历史栈**（⌘Z / ⇧⌘Z） | <> |
| 什么**进栈**、什么**不进栈** | ⭐ **选择变化绝不进栈**（否则按 ⌘Z 会撤到别处去） |
| 撤销深度 | 📐 **不设不必要的上限**；期望能撤回到打开或上次保存时 |
| 菜单项的**描述性标签** | 「撤销 <做了什么>」，不是光写「撤销」 |
| **撤销后结果不在视口内怎么办** | 📐 **必须滚动过去**——看不见的人会以为没生效然后重复按 |
| 不可撤销操作清单 | <显式列出。这些走「输入被销毁对象的名字」级确认> |

### 快捷键
| 层 | 本项目的键位 |
|---|---|
| 系统级（绝不覆盖） | ⌘Q ⌘W ⌘Tab ⌘空格 … |
| 应用级（任何视图下含义不变） | <> |
| 视图级（仅该视图生效） | <> |

- 焦点在输入框时，**除 Esc 与提交键外，无修饰键的单键快捷键让位**
- 同一动作在不同视图下**键位必须相同**
- 可发现性三处：菜单显示键位 · ⌘K 结果显示键位 · `?` 打开总览
- ⛔ **键盘发起的动作永不加动画**

### 焦点管理
- 容器模式（三选一，不许混用）：☐ Grid　☐ Toolbar　☐ Feed
- roving tabindex 还是 `aria-activedescendant`：<选一种>
- 焦点指示器：焦点环用于文本框/图像 · **高亮整行**用于列表与集合；2px + 2px 偏移，对比度 ≥3:1
- 📐 **焦点不许无用户交互而改变**；聚焦项消失时：方向键导航中→移到最近的剩余项，否则→隐藏焦点指示器

### ⭐⭐ 场景清单 → **改由 `spec/states.json` 产出**（2026-09-03）

⚠️ **这一栏 08-31 加进模板时理由是充分的**：G3 要用 `功能+端+状态` 三元键逐场景对账，
而没有任何上游产物负责给场景命名。
⛔ **但它是一张手维护的表，而且没有任何门禁查它在不在。**
📌 实测：08-31 之后写成的那份真实规格（云端办公 Agent，22 个界面、40KB），
**「场景清单」出现 0 次、「路由表」出现 0 次**，S5 的门禁全绿。
⭐ **一个没人守的必填项，在真实项目上的表现与不存在没有区别。**

**现在的做法**：场景 ID 由 `spec/states.json` 机械生成
（`surfaces[].id` × `ends[]` × 适用状态 = `fNN-端-状态`），
`scenario-matrix-gate.mjs` 逐个**真的触发一遍**，
runtime 把它写进 `body[data-scene]`——G3 的对账键照旧成立，且不再靠人手抄。

下面这张表**保留为人读的摘要**（想写就写，不写不影响对账）：

| 场景 ID | 对应 `FR/AC` | 这个场景是什么 | 端 | 状态（英文 slug） |
|---|---|---|---|---|
| `f01-pc-empty` | FR-011 · AC-1 | 首次进入、无数据 | pc | empty |
| `f01-mobile-empty` | FR-011 · AC-1 | 同上，移动端 | mobile | empty |
| `f01-pc-loading` | FR-011 | 导入进行中 | pc | loading |

**命名**：`fNN[-端]-<状态>`；端可省（单端产品），省略时按 `*` 匹配任意端。
⛔ **状态段用英文 slug**（`empty`/`loading`/`error`…），
与 Figma 图层名第三段、demo 的 `data-scene`**逐字相同**。
⭐ 中文展示名想写就写在「这个场景是什么」列——**展示名给人看，slug 给对账用**。

**下游三处引用的是 `spec/states.json`（不是这张摘要表）**：
S6 的 `data-scene` · S7 的 Figma 图层名 · **S8 的用例场景覆盖**。

### ⭐⭐ 元素标识表 → **单一源是 `spec/elements.json`**（2026-09-03）

⚠️ 此前元素身份有**两个源**：这张 md 表（`element-identity-gate` 读它）与
`spec/elements.json`（`spec-sync-gate` 读它）。两处各写一遍必然分叉，
⛔ **而分叉那天两道门都还是绿的** —— 它们各看各的那一份。
⇒ `element-identity-gate.py` 现在**两种输入都认**，项目**只维护一份**。
建议维护 json（下游 demo / 用例 / Figma 都直接消费它），本节放渲染后的表或直接引用文件。

⭐ 身份是**两层**：`id`（跨产物 slug，进 DOM 的 `data-el`、Figma 图层名、测试选择器）
+ `role` + `name`（可访问名称，用户能感知的那一层）。只有一层都会漏：
只有 slug → 改掉可访问名称，无障碍静默退化；只有 role+name → 改一句文案，
Figma 图层名与测试选择器同时失效。

以下表格保留为**人读的渲染**：

**同一个标识符必须原样出现在四个地方**，这样它们才对得上：

| 出现在哪 | 形态 |
|---|---|
| 本表 | 标识符本体 |
| HTML 交互稿 | `id="..."` |
| Figma 图层名 | 同名 |
| 测试用例的选择器 | 同名（或 `data-testid`） |

> ⛔⛔ **可访问名不走这条链**（2026-08-31 修，外部评审揪出）。
> 本表此前要求「`id` **且** `aria-label`」——**那是错的**：
> **给所有节点强塞 `aria-label` 会盖掉更好的可见名称。**
>
> | 身份 | 用什么 | 谁读它 |
> |---|---|---|
> | **稳定元素 ID** | `id="<标识符>"` | 定位、对账、Figma 图层名 |
> | **可访问名** | ⭐ **优先用可见文字**；表单用 `<label for>`；<br>复杂关系用 `aria-labelledby`；<br>**只有没有可见名称的图标按钮才用 `aria-label`** | 屏幕阅读器 |
> | **测试选择器** | `data-testid`（独立属性；⛔ 不复用 DOM id——id 另担页面内唯一性/锚点职责） | 自动化用例 |
> | **Figma 语义层名** | 同标识符 | 设计-研发对账 |
>
> ⭐ **它们必须能互相映射，但不必是同一个字符串。**
> ⚠️ 一个写着「保存」的按钮，`aria-label="save-btn"` 会让屏幕阅读器念出
> **比可见文字更差的名字**——这是净损失。

⚠️ **不这么做的后果不是「不规范」，是四处各叫各的名字、谁也对不上谁**——
交互稿改了一个按钮，Figma 里找不到它是哪个，用例里的选择器悄悄失效。
M1 的 ID 链管的是**条目**（需求/机会/假设），**这一层管的是界面元素**，此前没有。

| 标识符 | 类型 | 归属区块 | 用途（这个元素的活儿） | 触发它的用户动作 | 服务哪条需求/驱动力 | 怎么算成功 |
|---|---|---|---|---|---|---|
| `<页面>-header` | 容器 | — | 页头 | — | — | — |
| `<页面>-primary-cta` | 交互 | header | 发起注册流程 | 读完价值主张后点击 | `FR-003` | 进入第二步 |
| `<页面>-input-email` | 输入 | form | 收邮箱 | 点击/Tab 聚焦 | `FR-003` | 通过校验 |
| `<页面>-error-email` | 反馈 | form | 邮箱格式不对时出现 | 失焦或提交 | `FR-003` | 用户改对 |

#### ⭐ 命名规则：**按功能命名，不按内容命名**

| ✅ 好（功能） | ❌ 坏（内容/外观/位置） | 为什么坏 |
|---|---|---|
| `hero-headline` | `welcome-message` | **文案会变**，功能不变 |
| `primary-cta` | `blue-button` | **颜色会变**（而且它把令牌钉死在名字里） |
| `feature-benefit-section` | `first-paragraph` | **位置不是用途** |
| `form-validation-error` | `email-error-text` | 太具体，复用不了 |

结构容器：`{页面}-page` / `-header` / `-main` / `-form` / `-{区块}-section`
交互元素：`{页面}-{区块}-{元素}` / `-input-{字段}` / `-button-{动作}` / `-error-{字段}`

#### ⛔ 逻辑解释测试（写规格之前先过）
> **「我能不能不含糊地说清这东西为什么存在、怎么工作？」**

- ✅「这个按钮发起注册流程，服务于用户『想觉得自己准备好了』这个动机」
- ❌「这儿有个按钮……因为用户需要吧？」

**逻辑上的空缺会原样变成代码里的 bug。** 说不清就先别写规格，回去想。
⚠️ 上表的**「服务哪条需求/驱动力」一栏就是这个测试的落点**——填不出来的元素，
要么是没想清楚，要么它根本不该在这一页上。
